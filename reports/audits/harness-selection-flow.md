## 3. Landmine cross-reference

- **#2092**: root cause and fix surface confirmed. Main carries the loud-bind verify (`harness_binding.go:258-273`, PRs #2088/#2089 per `worklogs/1289_2026-11-17_refresh-compute-crd-skew-phase-starvation.md`) but NOT the UX/probe/alerting layer (`fix/2092-crd-skew-convergence` @ `a64c8541b` unmerged — the charter's "tsk-yeasty-magnet-scores" hardening). In THIS flow the skew manifests exactly as the charter predicted: picker (or silent bind) → 500 → generic alert → Creating forever. On pre-.16 API builds it was a 200 + silent wedge; on current main it is at least loud server-side, laundered to a generic alert client-side (D3).
- **PR 2085 rework history**: initial `6e73f7cc6` (2026-11-16) → review r3 `9776214fb` (decode-seam pin, honest denial classes, dup-comment removal — all backend/router-side). **Final-state weak spots the review did not close**: the dialog's `error` prop is dead in the live wiring (D3) and ChatPage has no picker entrance (D1). Both survive because review focused on the wire contract, not the surfaced UX.
- **Picker story AC** (worklog 1292): single-option auto-bind ✅ (`Sidebar.tsx:443-450`); badge after binding ✅ (`Sidebar.tsx:515` + pins); zero switch affordances ✅ (absence pins; read-only badge/settings row). The charter's AC all hold in code.

## 4. Verdict on the owner's symptom

**On a HEALTHY cluster (CRD current):**
- The flow works end-to-end: create (born-unbound) → sidebar + → picker (only when `harness.enabled` lists `pi`) or silent opencode bind (default) → atomic bind+create → Creating→Active → session → first message. No desktop-visible functional break.
- Two real frontend defects remain: **D1** (no ChatPage picker entrance; false "a few seconds" copy; mobile dead-end) and **D3** (all bind/create failure classes laundered to one generic alert), plus the latent **D4** and hygiene **D5**. None blocks a determined desktop user; all degrade first-run discoverability and failure diagnosis.
- **Configuration expectation check:** if prod has NOT set `harness.enabled=["opencode","pi"]` (default is `["opencode"]`, `pkg/settings/registry.go:73`; no pi runtime wired in default values), then "harness selection doesn't work" is **by design**: the picker never shows; + silently binds opencode. Verify this before blaming code.

**On the SKEWED prod cluster (pre-0.44.15 Workspace CRD):**
- Essentially 100% of the functional breakage is **#2092**: every bind is pruned; current main answers the loud 500 `harness_bind_not_persisted` (with the exact `kubectl apply -f helm/crds/workspace.yaml` remediation) but the UI shows only "Failed to create session." (D3), the workspace parks in `Creating` forever, the badge never appears, and session-create never succeeds. This is not a frontend bug — it is the operator-side CRD wedge; **the symptom disappears when the CRD lands**, leaving D1/D3/D5 as the residual code findings either way (D3 is what made the skew undiagnosable from the UI).
- Recommended sequencing: (1) operator applies the CRD (or merges/deploys the `fix/2092` branch for the refusal-at-create + amber-hint UX), (2) file D1+D3 as frontend stories (error surfacing + unbound Creating panel), (3) optional D2 as the cheap enabler for both.

## 5. PR decision

**Findings only — no PR.** The candidate fixes are not trivial-and-unambiguous: D3 has a real UX decision (alert vs keeping the dialog open with the inline error vs banner — the surface exists but the interaction choice doesn't), D1/D2 change what the transitioning panel renders and need product wording, D4 is a latent-defense judgment call, D5 is behavior-neutral hygiene on a shared component. Per the charter these get filed as stories by the orchestrator.
