# Worklog: Go 1.26.6 toolchain bump

**Date:** 2026-08-14
**PR:** #853

---

## Context

govulncheck began failing on every open PR: 7 Go stdlib CVEs
(GO-2026-6218, -6091, -6090, -6089, -6088, -5972, -5026) published
against 1.25.x after v0.15.4's release scan. Root fix: bump to
1.26.6 (verified locally red→green: 7 → 0 affecting vulns).

## What 1.26 surfaced (the interesting part)

Go 1.26's stricter net/url parsing (keyed to the go.mod language
directive — empirically confirmed by the reviewer: a `go 1.24` module
parses `http://host:port1:port2` leniently; `go 1.26` rejects)
exposed a latent panic class: **`req, _ := http.NewRequestWithContext`
with the error discarded → nil request → `Do(nil)` SIGSEGV**.

Fixed sites (all verified reachable in production):
1. `agent_reload.go` Reload — malformed pod IP → panic through gin
2. `agent_reload.go` reloadOne (bulk NDJSON) — same input class
3. `workflows/engine.go` PreserveOnFailure delete — **sessionID from
   workspace agent output** → control chars → panic in the scheduler,
   OUTSIDE gin recovery → API process crash (tenant→control-plane DoS)
4. `mcp_server.go` mcpSessionList/Read — external sessionID in URL →
   panic at SetBasicAuth (before Do)
5. `workflow_execute.go` deleteOpencodeSession — sibling of 4

Also: two test fixtures passed host:port as the podIP parameter,
building double-port URLs that only ever worked via 1.25 laxness +
routingTransport host rewrites. Fixed to bare hosts (SplitHostPort
with error check — IPv6-only runners yield [::1] which needs the
brackets stripped properly).
