## Objective

### `pkg/workflows/dag.go` — `ValidateSpec` pure function
9 validation passes:
1. **Empty spec** — reject specs with no nodes
2. **Duplicate node IDs** — reject duplicate IDs
3. **Invalid node types** — reject unsupported types (only script/agent/http/condition valid in v1)
4. **Node data validation** — required fields per type (handler+language for script, prompt for agent, url for http, conditions for condition)
5. **Dangling edges** — edge source/target must reference existing nodes
6. **Cycle detection** — Kahn's algorithm (topological sort via in-degree); also catches self-loops
7. **Multiple starts** — exactly one node with no incoming edges
8. **Unreachable nodes** — BFS from start; nodes not reachable are flagged
9. **Condition branch coverage** — every declared branch id + implicit "otherwise" must have an outgoing edge with matching `sourceHandle`
10. **Condition expression type-check** — expr-lang compile against predecessor's outputSchema (when schemas are provided)
11. **Defaults merging** — workflow-level `maxAttempts` and `timeout` applied to nodes that omit them (node-level wins)

## Key Decisions

1. **Kahn's algorithm for cycle detection** — not DFS. Kahn's naturally produces a topological sort and detects cycles when not all nodes are removed. Simpler to reason about than DFS-with-colors.
2. **Short-circuit on structural errors** — if there are dangling edges or duplicate IDs, the graph analysis (cycle/reachability) is unreliable. Return early.
3. **Condition expression type-check is opt-in** — caller passes a `predecessorSchemas` map; if nil, type-checking is skipped. This lets the handler decide when to enforce (e.g., always for UI-authored, skip for imported specs without schemas).
4. **Defaults merging mutates the spec in place** — the validated spec_json stored in the DB has defaults already applied. This means the executor sees a fully-resolved spec with no defaults ambiguity.
5. **ValidationError carries structured detail** — `Code` is machine-readable (UI can render per-code), `NodeID` scopes to the offending node, `Detail` is the human message.
