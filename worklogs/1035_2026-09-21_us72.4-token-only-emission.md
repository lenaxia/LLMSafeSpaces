## Design decisions (settled this session)

### D1 — The seam: `RelayTokenSource` on `SecretService`, nil = flag off

`pkg/secrets.RelayTokenSource` (interface) + `SetRelayTokenSource`. Production impl `k8sRelayTokenSource` (api/internal/app/relay_handoff.go): resolves the Workspace via the existing `k8sWorkspaceGetterAdapter`, reads `workspace-relay-<wsName>`/`handoff` in `ws.Namespace` through the API's existing clientset (app.go:1214 precedent). Absent Secret → `(nil, nil)` (not-ready, not an error); unparseable → error (both map to the builder's not-ready class). The handoff JSON shape lives in `pkg/secrets` (`RelayHandoff`/`RelayHandoffProvider`) with the exact tags of the controller's `relayHandoff` — parse-only single source; controller untouched.

### D2 — Token entries: decrypt for MODELS, never emit the key

Under flag-on with a staged handoff, each binding still decrypts server-side (trusted plane) and applies the model allowlist, so token entries are **byte-identical to the flag-off entries except `apiKey` and `baseURL`** (models + context limits survive — behavior parity for the pinned formatter). Then `applyRelayHandoff` swaps `apiKey = handoff.Token`, `baseURL = RouterURL + RouterPath` and attaches entry metadata `{relay: "true", relayExpiresAt, relayRevision}` (string-valued — the materializer's wire shape). The raw key value is dropped in the rewrite; the whole serialized batch is canary-grepped for raw-key bytes in tests. Lookup is by the DECRYPTED pd slug (the key the controller staged by — `ResolveLLMProviders` semantics); the relay path dedups on pd slug too (the staged set's key), while the flag-off path keeps its historical row-slug-only dedup **including duplicates** (pinned by `TestRelayBatch_FlagOffKeepsLegacyRowSlugDedup` — the bit-identity invariant cut both ways).

Providers absent from the handoff (non-frontable kinds — US-72.3 D5) keep the raw mixed-fleet path; an empty-token handoff entry (corruption the controller never writes) skips loudly (`relay_token_missing` audit), never a keyless entry and never a raw fallback.

### D3 — Missing handoff = staging-not-ready, class-muted

Flag-on + absent/erroring source ⇒ NO llm-provider entries at all (per-provider `credential_skipped_relay_not_ready` audits + the class-level `relay_staging_not_ready` audit + `BuildDegrade{relay_staging_not_ready}`, which wins over a co-present DEK degrade). Non-provider classes still deliver; the pod boots degraded-but-alive. The conditions machinery carries the cause from both nets: the controller's `CredentialsStaged=False` (US-72.3, the handoff is missing because staging failed) and — once the batch lands — agentd's relay slice reports nothing to watch.

### D4 — Manifest tier: one extra hash line

`ManifestHashWithRelayRevision(ownerID, entries, rev)` = `ManifestHash` + a `relay|<rev>` line after the owner line (empty rev degrades to EXACTLY the legacy hash). Both `BuildWorkspaceBatch` and `ManifestFor` go through `workspaceManifestHash` (one handoff read per build; the 304 path and the seq mint can never disagree). A handoff read failure degrades to the rows-only hash — worst case a no-op re-delivery, never a false 304. A ~TTL/2 renewal changes the revision → manifest hash → new seq → conditional-pull resync. No new delivery path (K6).

### D5 — Flag plumbing: same chart flag, narrow API rollback lever

API config `relayOnlyKeyDelivery.enabled` ← env `LLMSAFESPACES_RELAYONLYKEYDELIVERY_ENABLED` (BindEnv precedent `server.inferenceRelayURL`), rendered by api-deployment under `relayOnlyKeyDelivery.enabled && dig(api, enabled, true)`. `dig` not `default`: Helm's `default true` coerces an explicit `false` back to true. `relayOnlyKeyDelivery.api.enabled: false` (values, default true) is the builder-only rollback lever — controller staging + router stay up while raw-key batches resume (design §6.4). app.go wiring sits right after `NewSecretService` (~line 561), ~60 lines away from #1522's hunk (~622) — keep-both on merge; values.yaml append is inside the existing relay-only block (disjoint from #1523's `controller.agentdSidecar.uploadStaging`).

### D6 — agentd liveness: credential-level probe, local expiry, re-arm rides `startRearmLoop`

`relay_liveness.go`: a registry rescans the durable batch file every tick (relay-marked entries → {slug, baseURL, token-in-memory, expiry, revision}); the monitor (a) honors `relayExpiresAt` LOCALLY (`token_expired` needs no router), (b) probes `GET {baseURL}/models` with the scoped token — the exact request `EnrichProviders` issues; the router serves it from the staged catalog (zero upstream). Transport failure → `relay_unreachable`; the router's `{"error":"relay_rejected","reason":X}` body surfaces X verbatim (`credential_stale` / `scope_violation` / `sanitization_refused` / `quota_exceeded`; bare `unauthorized` → `credential_stale` — the wrong-pub corruption class, §4.2's one escalating cause). **This probe is the US-72.3 D7 "emission lands with US-72.4" feed** for the reject codes — continuous, not only-when-enriching (the enricher itself is untouched).

Loop shape: a healthy-cadence watchdog (30s default, env `LLMSAFESPACE_RELAY_LIVENESS_INTERVAL`; first tick immediate for boot detection) + a CAS-guarded `startRearmLoop` (loop label `relay_liveness`, #910 5m→30m backoff via the rearm loop's own MinDelay/MaxDelay) armed on the first degraded tick. The guard re-opens on success/absent (Attempt success or the Applied gate seeing the watchdog healed it) so a LATER outage re-arms again; exactly one re-arm in flight by construction. No Busy/RestartDeferred gates — a liveness probe restarts nothing and touches no session. No crashloop by construction: probe failure is state, never exit.

Surfacing: cached snapshot only (`stateMu` never held across I/O — probes serialize on `evalMu`). healthz (`Relay` field + `degraded:<code>` warning, never `Healthy=false`), readyz (`Relay` field, NEVER gates `Ready` — an outage must not drop endpoints), statusz (mirror). Tokens never logged, never in any `RelayHealth` field.

### D7 — Controller mirror + the lineage conjunct goes live (deviation-handled)

health.go merges `healthResp.Relay` into `SecretsDelivery`: the relay degrade code joins `DegradedReason` **winning over a co-present spawn_env_\* code** (its codes are class-critical for `classifyRelayStale`/`relayRouterRejection`; every co-present spawn_env_\* code maps to the same delivery class — no classification lost either way), and a healthy relay slice does NOT erase a real spawn degrade. New status field `SecretsDeliveryStatus.RelayRevision` mirrors agentd's applied relay revision.

**Scope note / small deviation:** the plan comment did not decompose the lineage-conjunct change, but US-72.3's handoff (0992 Next Steps) names it US-72.4's ("spawned_rev starts tracking the staged revision (which makes the lineage conjunct live)") — and as-landed, `relayLineageIntact` compared `sd.SpawnedRev == stagedRev`, which can NEVER hold (`SpawnedRev` is `<seq>:<manifestHash>:<contentHash>`, the staged revision is `r<hex>`). Adapted to the code: the conjunct now compares `sd.RelayRevision` (the relay batch metadata's revision, reported by agentd). Pre-US-72.4 runtimes report neither field → conjunct false → escalation stays structurally suppressed (the documented pre-flip semantics; pinned by `TestRelayLineage_SatisfiedByAppliedRelayRevision`). The three DR-test fixtures that simulated lineage via `SpawnedRev` were updated to the real signal.

### D8 — agentd emission: zero formatter/seam changes, pinned

No `pkg/agentd/secrets` or `pkg/agent/opencode` changes at all. Pinned by `TestRelayEmission_TokenNotKeyCanary_FormatterPin`: an all-relay batch through the REAL `LoadBatchFile` → `Materializer.Materialize` → `FormatProviders(FormatOpenCodeConfig)` emits the token into the formatted config (and `StagedProviders` carries it for the auth-store merge) and zero raw-key bytes. `EnrichProviders` through the router pinned by `TestRelayEmission_EnricherResolvesModelsThroughRouter` (path `/w/<ws>/<slug>/v1/models`, Bearer = the token). `shouldSkipRelay` untouched.
