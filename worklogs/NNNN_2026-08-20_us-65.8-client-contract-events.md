## Work Completed

### 1. The seam: `Adapter.ClientEventsFromEvent` + `RetryFromEvent`

- `pkg/agent`: two interface methods + `ClientRetryStatus` (retry detail is UI-shaped — rides the platform `session.status` channel, no contract change needed).
- `pkg/agent/opencode/client_events.go`: stateless per-event translation. Type-check-first (deltas — the hot majority — cost string compares only). Translation table:
  - `message.part.delta` → `EventPartDelta{SessionID, MessageID, PartID, Delta}`
  - `message.part.updated` → `EventPartEnd{Part: translatePart(...)}` — and a step-finish part instead yields `EventSessionUpdated{Session.ContextUsage}` (per-step occupancy preserved; the parse reuses `wire.ParseStepUsageProps`)
  - `session.updated` → `EventSessionUpdated{Title, ParentID}` — NEVER ContextUsage (cumulative-tokens trap, asserted by test)
  - `session.error` / `session.next.step.failed` → `EventError{Code, Message}` (providerID composed into the message — the contract Error has no provider field)
  - everything else → nil
- `translatePart` extracted from `translateMessage` (shared by history + bridge; step boundaries drop, unknowns → Custom per the discipline rule).

The `eventType == "session.updated"` dispatch literal is gone — the `eventLiteralKnownLeaks` map is now EMPTY and the knownLeaks comment records the retirement.
- E2E pin: `TestE2E_RealAdapter_ClientEventBridge` — three raw events through `onRawEvent` → broker receives contract usage (used=140), title, retry; DB persists usage + title from the translation.

## Key Decisions

| Decision | Rationale |
|---|---|
| Translate at the existing `onRawEvent` funnel, not via `Adapter.Stream` connections | `Adapter.Stream` opens a per-session SSE connection — a second upstream connection per session. The funnel already receives every event; a stateless translate-and-publish adds zero connections and zero new failure modes. |
| `session.event` as a NEW platform SSE type (contract Event as payload) | The existing synthesized `session.status` (idle/busry strings) stays untouched — no migration risk; contract events ride their own channel. The raw `agent.event` relay REMAINS for non-repo consumers (removal is a separate cleanup). |
| Retry as platform payload, not contract | Retry detail (attempt/message/next/action) is UI-shaped; growing the contract for it would be a design-0049 amendment with no second-consumer validation. |
| ProviderAuthError composes providerID into the message server-side | The contract Error has {code, message}; the UX keeps provider attribution without a contract change. |
| part.updated → EventPartEnd (snapshot semantics) | opencode's part.updated IS a snapshot; the frontend renderer is snapshot-driven. part.start/delta/end map naturally (deltas → part.delta; snapshots → part.end with full Part). |

Assumption validated: user-echo detection is text-matching against `sentTextRef` (no wire role needed) — confirmed by reading the old renderer before the rewrite.
