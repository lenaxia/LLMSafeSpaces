# Worklog: #817/#818 — self-healing send recovery + frontend reconcile

**Date:** 2026-08-15
**Issues:** #817, #818

---

## Context

Production v0.15.4: prompt POSTs 502 after exactly 2m5s while the LLM
turn completed server-side (messages persisted, session back to idle).
The #851 logging (v0.15.5) will name the transport error on the next
occurrence, but no repro has fired since. Rather than block user
recovery on an un reproduced middlebox bug, this change makes both
layers self-healing against the *signature*: send failed + turn
completed server-side.

#818 re-scope (comment 2026-08-15): the SSE transport already reconnects
(#25, 2026-06-05 — backoff, 35s read-timeout, reconnect→status
re-poll + reconcileOnIdle). The v0.15.4 incident was a live connection
delivering no events — transport reconnect can't fire on that. The
actionable gap was in `useChatStream`'s send-failure path: 502 →
setError only, never a history fetch.

## Approach

**API (#817)** — `proxy_send_recovery.go`:
- On `adapter.Send` failure (both SendMessage and SendPromptAsync
  adapter paths), probe `adapter.GetSession` (10s budget).
- Recover only when: session idle AND `time.completed` ≥ submit
  (−2s skew tolerance). Busy/unknown/stale-completion keep the 502 —
  the turn may still be running, or completed belongs to a prior turn.
- Fetch history (30s budget), return the newest assistant message as a
  normal 200 with the full success-path side effects
  (`postAdapterSuccess`: activity, session-index, metering; title
  fetch). The turn really happened — billing/index must record it.
- Never fabricate: history fetch failure or no assistant message →
  fall through to the existing 502 + #851 error log.

**Frontend (#818)** — `useChatStream.ts`:
- Reconcilable send errors: 502/504 and `TypeError` (fetch transport
  failures). 503 excluded (bounded retry loop owns restart windows),
  429 excluded (turn never started).
- On failure: wait for idle (SSE recovery or the existing 60s timeout —
  covers the wedged-SSE incident shape), then `getHistory`; deliver the
  newest assistant message only when its `createdAt` ≥ send start
  (−5s skew tolerance). Older → surface the error, never replay a
  stale response.
- Idle-wait helpers hoisted out of the try block (function declarations
  are block-scoped; the catch path needs them).
