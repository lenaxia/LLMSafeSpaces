# Worklog — silent-hang detection: worker_silent alert arm + board assignee_quiet surface (#2047)

**Date:** 2026-11-16
**Branch:** `fix/2040-worker-silent-alert`
**Issue:** [#2047](https://github.com/lenaxia/LLMSafeSpaces/issues/2047) (parent remediation: #2040 — the FMD-Web incident)

## What

The 2026-11-15 incident's workers were SILENT, not busy: `session_hung` fires on long **busy** age (`proxy_lifecycle.go` reads statusz `BusyAges`), but a session whose event table is static never accumulates busy age — the synthesized IDLE settles actively keep the busy view clean. Zero alerts fired while 3 of 4 board slots were held 4+ hours. Busy-age is structurally blind to silent hangs.

This lands the silent arm, three surfaces composed from one hub:

1. **The alert arm** (`api/internal/handlers/proxy_worker_silent.go`): per claimed `in_progress` board task, TWO stale legs must both be past `SilentWorkerThreshold` (default 30m) — the assignee's last **worker-activity** stamp (post-#2042/#2040 the liveness hub's index is worker-activity-only: MESSAGE_*/PART_* — a quiet stamp is a TRUE quiet) AND the task's `last_progress_at` (post-#2043 two-clock split: claim mints + worker heartbeats are the only writers). Both stale → one **session-scoped** `worker_silent` alert: `workspace.alert` SSE + a persisted `session_alerts` row carrying the task facts (task short id, project, lease state) so the on-call sees WHICH slot is held. Same cooldown/resolution discipline as `session_hung`: one alert per cooldown window, auto-resolve on resumed activity, notify-only.
2. **The board read surface** (`pkg/board/quiet.go` + hub): the GetTask/List/Search wire gains net-new `assigneeQuietSeconds` + `assigneeBusySeconds` — nil = unknown, never 0 — fed from a new `board.AssigneeQuietSource` seam (the `WithBusySource` house pattern: POOR and PURE, one batched question per read, no cursors).
3. **The hub quiet clock** (`api/internal/app/board_liveness.go` + `board_quiet_source.go`): the frame index's stamps are ordinals over one global counter (they ORDER activity but cannot TIME it) — a `framesWorkerAt` wall-clock companion is stamped in the same stroke and pruned in lockstep; `QuietFor(sessionID)` and the batched `AssigneeQuiet` ride it with BusyAssignees' guards verbatim (identity resolve, worker-stamp distrust gate, busyFn).

## Why this shape (decisions)

- **Unknown NEVER alerts** (the `bool=false` / nil path): a session this process has never stamped (hub restart, unindexed) is absence of evidence, not evidence of silence — #1685's fail-toward-silence precedent applied to absence. Unknown also never RESOLVES (no flapping; the read-side stale-heal bounds a lost-resolution dangler, exactly the d6 posture).
- **Busy truth vetoes the verdict**: derived-busy means mid-turn — a worker inside a tool call is ALIVE however silent (2026-10-29 ruling). `workerSilentEvidence` returns false on `Busy` before any other leg.
- **No new polling loop** (R4): the evaluator rides the state reconciler's existing alert pass (`reconcilePass` — the same tick as `escalateHungs`, in its own panic-isolated block). The board join is a NARROW seam (`handlers.QuietBoardLookup`, one method, wired `SetQuietBoardLookup` — the `SetFrameObserver` one-function style); the proxy never holds the board service. Nil seam = inert (board disabled, pre-wiring boot).
- **Session-scoped cooldown** (the fatigue contract): `silentAlerts` keys on (workspace, session) — 3 silent workers are 3 independent cooldowns and 3 distinct alerts, never one workspace-wide storm. Threshold floored at 30m, cooldown floored at `busyAlertCooldown` (never noisier than the busy arm); both clamps evaluated at read time (`silentWorkerThreshold()`/`silentWorkerCooldownWindow()`), not just documented.
- **`assigneeBusySeconds` definition, stated honestly**: there is no per-session busy-episode-since stamp anywhere today (the usagestream gate holds bools). The honest derivable figure is the QUIET clock's value at the moment derived-busy holds — how long the mid-turn worker has been frame-silent (a streaming worker sits near 0; a mid-`sleep 300` grows; both ALIVE). Fabricating episode-age state for a surface-only v1 would be state for state's sake; the definition rides "the same quiet query + the busy source" exactly as the issue words it.
- **Wire fields camelCase** (owner decision 2026-11-15): `assigneeQuietSeconds`/`assigneeBusySeconds` match the heartbeat-response precedent (`leaseExpiresAt`/`lastProgressAt`, `board_automation.go:101`) — deliberately NOT the row-shape snake_case the Task struct otherwise uses; the contract test pins the exact keys.
- **Persistence: payload column, not signature creep** (issue's "prefer payload JSON"): migration `000058` adds nullable `session_alerts.payload` JSONB + the `(workspace_id, session_id) WHERE resolved_at IS NULL` partial index for the session-scoped resolve. `InsertSessionAlert` grows a nil-able `facts map[string]string`; `SessionAlertsService` grows `RecordTaskAlert`/`ResolveSession` (new methods, not signature changes — the d6 callers stay byte-identical). Existing session_hung rows keep NULL payload forever (the conservative mid-deploy contract, pinned).
- **pending_input rows excluded** from the lookup: their worker is waiting on a HUMAN — not the silent-worker shape (000050's semantics).
- **Task-with-facts on the SSE event too**: the Data map carries `task_short_id`/`project_id`/`lease_state`/`assignee_quiet_seconds`/`last_progress_seconds` — the SSE path is the primary surface (sessionalerts' own durability note), the payload column is the durable echo.
