## Context

After the Epic 65 adapter migration and v0.15.3 (scanner buffer fix), a full
audit of #751 (SSE tracker) and #752 (frontend 1.18.10 drift) against current
`main` revealed that most findings were already fixed by prior PRs (#738, #748,
#757, #795), but several remained broken:

1. **#751 F1c** — `handleSessionUpdated` silently dropped events with incomplete
   billing fields (no log on any failure path)
2. **#751 F1a** — cost-as-object parsing silently returned zero (the
   `json.RawMessage` change prevented event drop but never extracted the value)
3. **#751 F2** — `sessionStartTime` keyed by bare `sessionID` while cleanup used
   `workspaceID:` prefix — entries never matched and leaked forever
4. **#751 F3** — `StopWatching` didn't wait for the subscribe goroutine to exit
   (reconnect race; the correct fix from closed PR #791, redone with tests)
5. **#752 F4** — cold-start busy detection checked `status === "active"` but the
   backend enum has no `"active"` value (`pkg/session/session.go:29`)
6. **#752 F5** — fixed 60s timeout produced false "interrupted" banners for
   legitimate long turns
7. **#752 F6** — unknown SSE event types silently dropped (no default branch)

## Changes

### Go SSE tracker (`api/internal/services/sse/tracker.go`)

- **F1c:** Warn log on incomplete billing fields (empty model ID, zero output,
  empty session ID). JSON parse error also promoted from Debug to Warn.
- **F1a:** Cost-as-object now extracts the `"cost"` field (CostUSD in `ocCost`),
  not `"total"` (which is TotalTokens — a token count, not dollars). Falls back
  to warn log on unrecognized shapes.
- **F2:** `sessionStartTime` re-keyed from bare `p.SessionID` to composite
  `workspaceID + ":" + p.SessionID`, matching the keying pattern of
  `sessionTokenSeen` and `sessionCostSeen`. This makes the prefix-based cleanup
  in `StopWatching` actually work.
- **F3:** `sync.WaitGroup` per workspace. `StopWatching` holds `subMu` through
  `wg.Wait()` and map cleanup, preventing concurrent `EnsureWatching` from
  racing. `Stop` also waits for all goroutines.

### Frontend

- **F4:** `seedBusy` accepts `status: "busy"` (the real backend enum value) in
  addition to `"active"` for backward compat (`SessionActivityProvider.tsx`).
- **F5:** No code change — the existing busy-guard at `useChatStream.ts:118`
  (`!serverBusyRef.current`) already prevents false "interrupted" banners when
  the server is still processing. Combined with v0.15.3's SSE scanner fix
  (which eliminates connection drops on large events), the 60s timeout is
  sufficient. The comment at `useChatStream.ts:6-12` documents this rationale.
- **F6:** Default branch with `console.debug` for unknown event types in both
  `ChatPage.tsx` and `SessionActivityProvider.tsx`. `KNOWN_EVENT_TYPES` hoisted
  to module level to avoid per-event allocation.
