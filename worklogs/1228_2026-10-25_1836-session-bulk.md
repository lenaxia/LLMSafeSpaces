## Design (per-item delegation — the #1937 core value, at the tool seam)

Every item is ONE full single-tool flow, serial, in order:
`resolveSessionRef` (the #1831/#1930 phrase/alias/raw dual-accept,
case-insensitive — "phrase-id and raw-id both accepted per item where
the single-shot tools do") → the pod-identity platform write
(`SessionArchive` / `PlatformSessionDelete`). The batch adds ONLY the
per-item envelope; there is no second write path, no platform change,
no concurrency.

### Contract clauses → implementation

1. **Per-item array**: `{results: [{id, status, archived_visibility?,
   error: {code, detail}}]}`. `id` echoes the caller's ref VERBATIM
   (the #1937 rule); `archived_visibility` rides done archive items
   (#1879 semantics — from ONE shared `forceArchivedSetRefresh` after
   the loop: refreshes this pod's cache AND verifies every done item;
   disagreeing/failed read → unverified, never a failed write, never
   fabricated freshness — the #1879 incident's lesson carried into the
   batch form and pinned).
2. **Idempotent retry**:
   - ARCHIVE: the platform seam is idempotent for repeat writes —
     `SetSessionArchivedStatus` (database.go:1410) always matches the
     root row (`si.session_id = $2` arm), so a repeat archive/unarchive
     writes the same value and returns success → done, NOT a conflict.
     Pinned by TestMCPSessionArchiveBulk_IdempotentResubmit (both
     submits all-done).
   - DELETE (destructive — the owner's recorded ruling applied to the
     session twin): absence ≡ miss ≡ foreign. The platform keys
     session_index on (workspace_id, session_id) and the pod identity
     scopes the workspace, so a foreign/absent/mistyped ref all 404 →
     the SAME bare `not_found` item; the resolve-miss path renders the
     same code. Re-submit never errors, never double-writes. Pinned by
     TestMCPSessionDeleteBulk_IdempotentResubmit_AbsenceRendersNotFound.
3. **Per-item validation**: blank/non-string entries render that
   item's `invalid_input` row (sessionBulkString +
   sessionBulkInvalidItem); the rest process (pinned:
   MalformedItemIsolation, NonStringEntryIsItemFailure). Batch-level
   problems (empty batch, over-cap) poison every item → whole-call
   refusal with ZERO wire calls (pinned: BatchLevelRefusals,
   MalformedItemAndCap).
4. **Cap 50**: `board.BulkMaxItems`, single-sourced from the merged
   #1937 constant (agentd already imports pkg/board); clear overflow
   error naming the cap; schema descriptions carry the 1-to-50 range.

### Deltas vs the board bulk (documented choices)

- **NOT-in-engine**: sessions have no PG engine in this repo's board
  sense — their state lives in the platform's session_index via the
  internal API. The per-item loop lives at the agentd tool seam
  (mcp_tools.go), which is where the single tools live; this is the
  same "per-item delegation to the single seam" shape with the seam
  being an HTTP hop. No platform change required (the internal routes
  are unchanged, and the archive route is already idempotent).
- **Self-delete guard is per item**: `self_delete_refused` sinks only
  the caller's own session; the batch keeps processing and the
  platform is never asked for the guarded item (pinned:
  SelfGuardItemIsolation, DispatcherReadsInjection). The caller
  identity is computed ONCE per call — `resolveCallerSession`,
  extracted behavior-identically from mcpDeleteSession (the injected
  session first, single-busy fallback on degraded pods, ambiguity
  allows).
- **Did-you-mean rides not_found details**: unlike the board bulk's
  never-disclose envelope (cross-USER perimeter), this surface is
  workspace-scoped by pod identity — there is no foreign-user class;
  the singles' #1663 suggest-only clauses are the established safe
  behavior and ride the item details verbatim.
- **REQUIRED DIRECTION is batch-level**: one shared `archived`
  boolean; omitted/non-bool refuses the whole call (the single tool's
  review-r1 discipline, amplified: a malformed direction must archive
  NOTHING). Pinned by MissingDirection_Refuses.
