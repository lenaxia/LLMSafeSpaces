## Design deltas vs #1937 (documented, all pinned)

1. **Idempotent retry for a DESTRUCTIVE variant — absence ≡ miss ≡
   foreign**: the claim/move pre-checks read observable row state
   (in_progress / at-target → done). A delete's "already-done" state
   is row ABSENCE, indistinguishable from a miss and from a foreign
   row. All three render the SAME bare `not_found` item (byte-equal
   code AND detail — the item is constructed identically for all
   three — each renders exactly what `NotFoundError{Item:"task",
   Identifier:<own ref>}` renders: same code, same detail template
   with the caller's own ref substituted, zero class information).
   Rendering absence as `done` would (a) fabricate an outcome
   for a foreign probe and (b) DISCLOSE foreign-row existence (an
   existing-but-foreign row returning not_found while an absent row
   returned done). Contract 2's substance — retry safety — holds: no
   batch error, no second write/audit/abort on re-submit (pinned:
   `TestBulk_DeleteIdempotentResubmit`,
   `TestBulk_DeleteTripleEqualityNeverDisclose`).
2. **One shared `reconnect` flag** across the batch (the
   BulkMoveStage shared-toStage pattern; per-item flags would be N
   single calls).
3. **Echo fields on done items**: `orphaned_dependents` +
   `reconnected` ride `BulkItemResult` (omitempty) — the single form's
   `DeleteResult` facts, surfaced so the sweep caller sees affected
   parties without an events round-trip (the issue's round-trip-economy
   mandate). Precedent: `Escalated` is the claim variant's
   variant-specific field. No token-class field ever renders (#1864
   ruling; pinned by the JSON-shape test).

## CI rounds 1-2 (Secrets Integration failures → fixed in-place)

Round 1: the byte-equality pins compared whole `BulkItemResult`
structs — but `Ref` echoes each caller's ref VERBATIM (by design), so
items for two different refs can never be structurally equal. Fixed
to compare error payloads.

Round 2 (the instructive one): the error `Detail` embeds the CALLER'S
OWN ref (`board: task "<ref>" not found`) — self-identifying, zero
class information, but not byte-equal across DIFFERENT refs. The
correct pin, now in place: every class (absence, miss, foreign)
renders EXACTLY what `NotFoundError{Item:"task", Identifier:<own
ref>}` renders — same code, same detail template with the caller's
ref substituted. An observer holding only the response cannot tell
the three classes apart — which IS the never-disclose property; the
earlier "byte-identical detail across different refs" phrasing
overreached (it would require suppressing the self-identifying ref
the single-task 404 also carries). Both fixes are assertion-side;
the implementation never changed. (Also the honest boundary note:
local PG absence is why these landed in CI, not locally.)
