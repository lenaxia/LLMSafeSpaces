### US-63.3 — Enqueue path (`proxy_v2.go`)

New file `api/internal/handlers/proxy_v2.go`:

- **`enqueueV2(c, wid, sid, text) bool`** — flag check → construct V2 client → `client.PromptV2(ctx, sid, text, V2DeliveryQueue)` → emit `queue.update/enqueued` SSE with the returned message ID → return 202 `{"messageID": resp.ID}`. Returns false if flag off (caller falls through to V1 Redis path).
- **`SendPromptAsync` V2 path** (inline at top of existing handler): reads the V1 parts body, extracts text via existing `extractPromptText`, calls `enqueueV2`. Bypasses the 409 guard (`isSessionActive` check), the queue-len check, and `redirectPromptToQueue` — opencode admits atomically, no 409 on busy.
- **`EnqueueMessage` V2 path** (after text validation, before Redis write): calls `enqueueV2`. The Redis write path is unreachable under the flag.

### US-63.4 — Abort path

- **`abortV2(c, wid, sid) bool`** — flag check → construct V2 client → `client.InterruptV2(ctx, sid)` → return 204. No Redis queue mutation (`PeekAll`+`Clear` bypassed), no `dismissed` SSE, no `flushAndAbortAfterIdle`. Queued messages survive and drain on the next `execution.wake` (F8).
- **`AbortSession` V2 path** (inline at top of existing handler): calls `abortV2`.

## Key Decisions

1. **V2 methods in a dedicated `proxy_v2.go` file**, not inlined in the 1029-line `proxy_handlers.go`. Isolates the opencode import; the handler modifications in `proxy_handlers.go` are flag-check + delegate calls (no opencode import needed there).

2. **V2 client does NOT share `h.httpClient`.** The proxy's shared HTTP client has no timeout (needed for streaming SSE). V2 calls are fast request-response (POST → 200/204). Using the shared client would make V2 calls hang indefinitely on unreachable pods. The opencode.NewClient default (10s timeout) is correct for V2.

3. **`enqueueV2` / `abortV2` return bool, not error.** The bool pattern ("did the V2 path handle this?") cleanly gates the fall-through to V1. The methods write the gin response themselves on the V2 path (success or error), so the caller just `return`s when true.

4. **V2 abort emits NO `dismissed` SSE.** The spike confirmed interrupt is non-destructive (F8): queued messages survive. `dismissed` would be a lie. The frontend pills persist briefly on abort — this is the intended new UX (US-63.6 handles frontend queue derivation).

5. **Text extraction reuses `extractPromptText`.** `SendPromptAsync` receives V1 `{parts:[...]}` bodies. The V2 API needs `{prompt:{text}}` (F18). The existing `extractPromptText` function already extracts text from parts — perfect reuse.
