## Objective

Under V2, `GET /queue` returns empty because msgqueue is bypassed. Users navigating to a session with pre-existing queued messages see no pills until the next SSE event. This story closes that gap with a Redis-backed shadow marker (Option B from the story).

---

## Implementation (Option B)

**`V2QueueShadow`** (`proxy_v2_shadow.go`): lightweight Redis hash per session storing `{messageID, text, enqueuedAt}` view-cache tuples.
- `Add`: called from the SSE bridge on PromptAdmitted events. Sets a 10-minute TTL so lost Prompted events (SSE disconnect, replica crash) self-heal — phantom pills expire automatically.
- `Remove`: called on Prompted events (message promoted) and on explicit dismissal (DeleteQueueMessage).
- `List`: called by ListQueue under V2. Returns typed `queuedMessageResponse` structs (not `gin.H` — Rule 1 compliance). Malformed hash data is silently skipped.
- `ClearAll`: called on session delete.
- Nil-safe: all methods are safe to call on a nil shadow (no-op).

**`ListQueue`** (`proxy_handlers.go`): under V2 flag + shadow available, reads from shadow instead of `queueSvc.PeekAll`.

**`DeleteQueueMessage`** (`proxy_handlers.go`): under V2 flag + shadow available, removes from shadow + emits `dismissed` SSE so dismissed messages don't reappear on fresh load.

**`app.go`**: injects cache service's Redis client.

Cross-replica: Redis-backed so any replica serves `GET /queue`. Best-effort: opencode's SQLite is authoritative; the shadow self-heals via TTL + next-event cycle.
