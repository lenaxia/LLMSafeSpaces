## Objective

A thin V2 session HTTP client that can send a prompt with `delivery` and issue an interrupt against opencode's V2 session API. This is the transport layer US-63.3 (enqueue) and US-63.4 (abort) will call instead of V1 `prompt_async`/`abort`. Coexists with V1 — no call-site migration in this story.

---

## Work Completed

### `pkg/agent/opencode/client_v2.go` — V2 methods on the existing `Client`

Two new methods on the existing `*Client` type (same baseURL, password, httpClient):

- **`PromptV2(ctx, sessionID, text, delivery) (*V2PromptResponse, error)`** — POST `/api/session/:sid/prompt` with `{prompt:{text}, delivery}`. Returns decoded `{admittedSeq, id, sessionID}` on 200.
- **`InterruptV2(ctx, sessionID) error`** — POST `/api/session/:sid/interrupt` with `{}`. Non-destructive (F8: queue survives). Returns nil on 204 (idle or in-flight).

Supporting types: `V2Delivery` (`"queue"` | `"steer"`), `V2PromptResponse`, error sentinels `ErrV2PromptConflict` / `ErrV2SessionNotFound`.

### Feature flag: `config.SessionQueue.V2Enabled`

Added `SessionQueue.V2Enabled bool` to `api/internal/config/config.go` (default false). Env override `LLMSAFESPACES_V2_SESSION_QUEUE=true`. The client itself is pure transport — the flag is checked at call sites in US-63.3/63.4, not here.

### Tests: `client_v2_test.go` (10 tests, all PASS)

- Success: prompt response decoded, path/method verified, auth header verified
- **F17**: request body verified to contain NO `id` field (PromptConflictError avoidance)

## Key Decisions

1. **F18 deviation from story spec (load-bearing).** The story spec says the body is `{prompt:{parts:[...]}}`. The spike (worklog 0703, finding F18) proved opencode 1.18.10 **rejects** parts with HTTP 400 `Missing key at ["prompt"]["text"]` and requires `{prompt:{text:"..."}}`. The client uses the spike-verified text shape. Documented in the `v2PromptRequest` struct comment. When opencode is bumped to a version that accepts parts, this struct changes — the schema-pin pattern from `configwriter_test.go` should be applied then.

2. **`workspaceID` omitted from the method signature.** The story spec says `PromptV2(ctx, workspaceID, sessionID, body)`. The existing `Client` is constructed per-workspace by callers (`agent_reload.go:226`: `NewClient(fmt.Sprintf("http://%s:%d", podIP, port), pw, ...)`), so the baseURL already targets the right pod. Adding workspaceID would be dead weight — the Client has no K8s client to resolve pods from. Matches the V1 method pattern (`DisposeInstance`, `GetSessionStatuses`, `ListModels` all omit it).

3. **`resume` omitted from the request body.** The story mentions `resume`. F15 confirmed no resume endpoint or parameter exists on 1.18.10. Documented in the struct comment; add it when a spike verifies the parameter exists.

4. **Delivery is a required parameter (no default).** The spike noted delivery defaults to `"steer"` when omitted. Making it required is safer — the caller (US-63.3) must be explicit about queue vs steer. No silent default.

5. **Error sentinels are distinct from V1.** `ErrV2PromptConflict` / `ErrV2SessionNotFound` are V2-specific failure modes. Callers branch on these to decide retry vs. surface-to-user. The V1 client has no equivalent (V1 auto-creates sessions and silently discards on busy).
