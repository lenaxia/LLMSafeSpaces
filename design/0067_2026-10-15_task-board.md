## 1. The problem, in half a page

The platform can run agents (workspaces, sessions, workflows, triggers) but cannot *manage work for them*: an orchestrator's "fix bug X, then review PR Y" lives in a chat transcript, dispatch is ad-hoc (`create_session` + hope), and when a worker dies mid-task nothing reclaims the work. The Task Board adds the missing layer: projects → epics → tasks with stages, an auto-dispatch engine that feeds ready work to worker sessions, and a reconciler that converges board truth when workers die, PRs merge, or operators cancel mid-flight. (Entity shape per the 2026-10-16 consolidated rulings, §2b — the original sketch's stories are cut.)

Three platform facts make this tractable now rather than novel: (i) the trigger/workflow lane (Epic 64) already established the dual user/org owner model, the REST+MCP parity discipline, and the internal automation seam agentd uses to act on platform objects (`cmd/workspace-agentd/mcp_tools.go:1293`); (ii) design 0066 (PR #1693) built the short-ID mint + did-you-mean machinery the board's identifiers reuse directly; (iii) the #1643/#1685 lanes established that liveness is **evidence, not elapsed time** — the exact semantics a lease/heartbeat engine needs. The board is the composition of these, not a new architecture.

## 2. Settled rulings (owner-approved in #1696 — transcribed verbatim)

> ### Entities & inheritance
> - Projects (swimlane): target workspace, worker count config, tags. Epics per project (default DRAFT; activate → auto-feed work to workers until done; pause stops new claims).
> - Stories (per epic), Tasks (per story or directly per epic). Stages: Backlog → In Progress → In Review → Done + Pending Input (maps to agent.question/permission) + Cancelled (terminal, lease-revoking + worker-abort; reconciler can never resurrect).
> - BLOCKED is orthogonal to stage: item-link (unblocked when target Done) OR natural-language criteria evaluated by LLM (call_with_model, cheap model, on-demand + low-frequency sweep, evidence stored).
> - Display inheritance (materialized at write, rename = one UPDATE): all items carry project name; stories/tasks carry epic name; tags on every entity; indexed filters.
>
> ### Identifiers (reuse #1691 pattern)
> prj-/epc-/sty-/tsk- + 8 chars lowercase+digits, per-project uniqueness, did-you-mean 404+suggestions on every resolution surface. FKs are identity; names/paths are display data.
>
> ### Priority & fairness
> P0–P3 on epics + tasks (default P2). Ready-set order = (priority, virtual_finish_time) — deficit round robin across projects/epics so no epic starves another. UI priority changes enter the queue legitimately.
>
> ### Dispatch engine (self-healing by convergence)
> - Postgres arbitration: atomic claim (UPDATE...WHERE unclaimed RETURNING), no in-memory scheduler state.
> - Leases + heartbeats (reuse #1685 message-level progress evidence); lease lapse → auto-reclaim to Backlog, attempts++; attempts ≥ N → Pending Input escalation.
> - Reconciler sweep (incremental watermark): lease reclaims; external-truth drift (PR merged → Done; closed-unmerged → In Progress); criteria re-eval; epic completion. Cancelled immutable-terminal.
> - Idempotent writes (claim tokens + event IDs — outbox clientMessageID discipline). Provider throttles: 429 = worker-slot cooldown + requeue WITHOUT attempt penalty (platform-level backoff is the real fix, board displays health).
>
> ### Surface model — ONE canonical action layer, four projections
> All guards/validation/idempotency/audit live once in BoardService. Projections: (a) REST for UI + SDKs (openapi canonical, 4 SDKs, canaries, freeze gate, BREAKING discipline — full product contract tier); (b) EXTERNAL platform MCP server (customer-facing board.* tools, same handlers, customer authz); (c) agent-internal MCP registry (agentd/origin-plugin pattern; adds claim-token semantics); (d) frontend Board UI beside Triggers/Workflows.
> - UI action set (parity across ALL surfaces): drag=move_stage (optimistic, server-arbitrated snap-back), PATCH item, task:start (manual one-off dispatch even in draft epics), epic:activate/pause, cancel (task/story/epic), CRUD, board read model + SSE live feed.
> - PARITY IS PINNED: contract-test matrix asserting every action expressible via REST + both MCP registries with identical guard outcomes.
>
> ### Authz (dual granularity)
> owner_kind: user|org on projects (cascades). User-scope: private boards, personal workspaces. Org-scope: role-gated (owner/admin full; member matrix = OPEN RULING), org workspaces only (v1). Workers delegate as their user; claim tokens are the in-flight guard. UI scope switcher Personal | <Org>.
>
> ### Frontend
> Kanban: columns=stages, swimlanes=projects; epic chips, tag filters, search with did-you-mean. Cards: short ID, priority, tags, blocked badge (+Evaluate-now), assignee busy indicator (the #1687-hardened one), attempt counter. Epic drawer: progress, activate/pause, worker budget, SSE activity feed. Health panel: leases, reclaims, cooldowns, pending criteria evals.
>
> ### Self-healing test invariants (red-first lane discipline)
> Kill worker mid-lease → task reclaims. Merge PR without stage move → converges to Done. Cancel mid-flight → worker aborted, never resurrects. Crash between action and effect → idempotent replay converges.

**First ruling (blocking model):**

> **OWNER RULING — blocking model simplified (supersedes the criteria sketch):** blocked is **purely structural — `depends_on[]` is the ONLY blocking mechanism. No free-text/criteria blocks exist.**
>
> Consequences for the design:
> 1. DELETE the blocked_criteria machinery entirely: no `blocked_criteria` field, no LLM evaluator, no witnesses, no verdict records, no sweeps of prose, no "unclear" state, no `board.evaluate` tool, no evaluate-now UI. The engine shrinks accordingly (reconciler loses the criteria direction; #1698 scope reduces).
> 2. **External conditions become explicit board items**: "wait for provider 429 resolution" is a TASK (owning its evidence — acceptance criteria, evidence_url, activity feed) that other tasks `depends_on`. External waits inherit the full item machinery for free: identified, staged, Done-needs-evidence, filterable, cancellable — and unblocking stays instant/event-driven (target Done → dependents ready). The cancelled-dependency policy (dependents → Pending Input) covers abandoned external waits unchanged.
> 3. The blocked badge is purely structural: 🔗 N with live stage chips; the reverse-edge "blocked by" view stands.
> 4. **Scope guard — this ruling is about BLOCKS only**: `acceptance_criteria[]` on tasks REMAINS (it defines Done, judged at review time — not a blocking mechanism). Do not over-apply.

**Consolidated ruling set (R1–R5, authoritative):**

> **OWNER RULING SET (consolidated) — supersedes conflicting parts of this issue's original sketch. The design doc must transcribe these verbatim as rulings.**
>
> **R1 — Entities: epic + task only.** No stories, no group field. Grouping is covered by epic (coarse) + tags (free) + depends_on (semantic) — three mechanisms for one dimension was ceremony. If deep hierarchy is ever needed later, the additive path is self-referencing parent-tasks — not a v1 concern.
>
> **R2 — Field model (the full vocabulary):**
> - Task: id, epic_id, title, description (markdown — seeds the worker charter), acceptance_criteria[] (checkable, LLM-verifiable; **Done = all criteria met + evidence** — self-defining done), priority P0–P3 (default P2), stage + evidence_url per transition, depends_on[], assignee_session, claim_token, lease_expires_at, attempts, last_progress_at (message-level, #1685 semantics), stage-transition timestamps (**measured actuals — cycle time — instead of estimates; NO story-points field, deliberately**), tags[].
> - Epic: id, project_id, title, outcome (the human's steering wheel), status (draft/active/paused/completed/archived), priority, tags. **Progress is derived, never stored** (Done/(total−Cancelled), optionally criteria-weighted).
>
> **R3 — Blocking is purely structural (already relayed, restated for completeness):** depends_on[] is the ONLY blocking mechanism; no free-text criteria, no LLM evaluator, no witnesses/verdicts/sweeps/evaluate tools. External conditions become explicit board items other tasks depend_on. acceptance_criteria[] is UNAFFECTED (defines Done, not blocking).
>
> **R4 — depends_on semantics:** N-ary edges, unblocks when ALL targets Done. Three engineering obligations: (a) cycle rejection at write (409 + did-you-mean); (b) ready-set scheduling — ready = Backlog + deps satisfied; ordered by (priority, virtual_finish_time) deficit-round-robin — no topological sort, the DAG constrains, priority tiebreaks, fairness policies; (c) cancelled-dependency policy: dependents auto-flip to Pending Input with "dependency abandoned". Scoping: within a project (cross-epic allowed), never cross-project (authz + fairness boundary).
>
> **R5 — No formal DAG entities/milestones/phases:** workflows are the static-DAG product; the board is the dynamic-backlog product. Complementary, not overlapping.

## 4. The design

### 4.1 Entity model, schema, migrations

One migration (`000036_task_board.up/.down`), four tables plus an event log, following the 000016 conventions (CHECK constraints inline, `DO $$` constraint creation, partial indexes, `update_updated_at` triggers). **Entity set per ruling R1: project → epic → task. No stories, no group field** (grouping = epic + tags + depends_on; the future additive path for depth is self-referencing parent-tasks, explicitly not a v1 concern).

```
projects (
  id            uuid PK,
  short_id      text NOT NULL,                 -- prj-XXXXXXXX
  owner_kind    text NOT NULL CHECK ('user','org'),
  owner_id      text NOT NULL,                 -- user id or org id
  name          text NOT NULL,
  target_workspace_id uuid REFERENCES workspaces(id),   -- v1: single target (§8 OR2)
  worker_slots  int NOT NULL DEFAULT 2,        -- max concurrent in-flight claims (enforced by the claim CTE, §4.4)
  slot_cooldown_until timestamptz NULL,        -- provider-throttle: pauses NEW claims into this project (§4.4)
  tags          text[] NOT NULL DEFAULT '{}',
  status        text NOT NULL DEFAULT 'active' CHECK ('active','archived'),
  created_at/updated_at,
  UNIQUE (owner_kind, owner_id, short_id)
)

epics (
  id            uuid PK,
  project_id    uuid NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
  short_id      text NOT NULL,                 -- epc-XXXXXXXX
  title         text NOT NULL,
  outcome       text NOT NULL DEFAULT '',      -- the human's steering wheel (ruling R2): what this epic exists to achieve
  status        text NOT NULL DEFAULT 'draft' CHECK ('draft','active','paused','completed','archived'),
  priority      text NOT NULL DEFAULT 'P2' CHECK ('P0','P1','P2','P3'),
  -- display inheritance, materialized (ruling):
  project_name  text NOT NULL,
  tags          text[] NOT NULL DEFAULT '{}',
  -- (progress is DERIVED, never stored — ruling R2: Done/(total−Cancelled), optionally criteria-weighted; §4.2 board_read)
  -- DRR state (per-epic; Postgres is the only state, §4.4):
  vft           bigint NOT NULL DEFAULT 0,     -- virtual finish time: claims served (unit cost ⇒ globally comparable)
  deficit       bigint NOT NULL DEFAULT 0,     -- DRR deficit: claims consumed this round
  quantum       int NOT NULL DEFAULT 1,        -- DRR round allowance: claims per round (config, default 1)
  created_at/updated_at,
  UNIQUE (project_id, short_id),
  UNIQUE (id, project_id)                      -- composite-FK anchor for same-project children (below)
)

tasks (
  id            uuid PK,
  project_id    uuid NOT NULL REFERENCES projects(id) ON DELETE CASCADE,  -- denormalized: uniqueness scope + inheritance
  epic_id       uuid NOT NULL,                 -- composite FK below guarantees same-project parent
  short_id      text NOT NULL,                 -- tsk-XXXXXXXX
  title         text NOT NULL,
  description   text NOT NULL DEFAULT '',      -- markdown; seeds the worker charter (ruling R2)
  stage         text NOT NULL DEFAULT 'backlog' CHECK ('backlog','in_progress','in_review','done','pending_input','cancelled'),
  priority      text NOT NULL DEFAULT 'P2' CHECK ('P0','P1','P2','P3'),
  project_name  text NOT NULL, epic_name text NOT NULL, tags text[],
  -- Done evidence (ruling R3 scope guard: defines Done, never blocks):
  acceptance_criteria jsonb NOT NULL DEFAULT '[]',  -- [{text, met}] — checkable, LLM-verifiable; Done = ALL met + evidence
  -- blocking (ruling R3/R4: purely structural, derived from board_dependencies):
  is_blocked    boolean NOT NULL DEFAULT false,   -- materialized derivation (§4.1-edges); converges via the RC3 sweep
  -- dispatch state (Postgres-arbitrated, §4.4):
  assignee_session text NULL,                  -- worker identity: workspace_id + session short id (§4.4 task_start: manual form)
  claim_token   uuid NULL,                     -- set while claimed; the in-flight guard
  lease_expires_at timestamptz NULL,
  last_progress_at timestamptz NULL,           -- message-level progress watermark, #1685 semantics (§4.4)
  attempts      int NOT NULL DEFAULT 0,        -- CLAIMS made, incremented by the claim statement ONLY (§4.4)
  cooldown_until timestamptz NULL,             -- provider-throttle cooldown (per task, §4.4)
  stage_entered_at timestamptz NOT NULL DEFAULT now(),  -- current stage age; history in board_transitions
  created_at/updated_at,
  UNIQUE (project_id, short_id),
  FOREIGN KEY (epic_id, project_id) REFERENCES epics (id, project_id)   -- same-project parent, structural
)

board_dependencies (                            -- ruling R4: N-ary task→task edges, within a project (cross-epic allowed), never cross-project
  task_id            uuid NOT NULL REFERENCES tasks(id) ON DELETE CASCADE,
  depends_on_task_id uuid NOT NULL REFERENCES tasks(id) ON DELETE CASCADE,
  created_by         text NOT NULL,             -- actor (user id / system)
  created_at         timestamptz NOT NULL,
  PRIMARY KEY (task_id, depends_on_task_id)
)

board_transitions (                             -- ruling R2: evidence_url per transition + stage-transition timestamps (measured cycle time)
  id           bigint GENERATED ALWAYS AS IDENTITY PK,
  task_id      uuid NOT NULL REFERENCES tasks(id) ON DELETE CASCADE,
  from_stage   text NOT NULL,
  to_stage     text NOT NULL,
  evidence_url text NULL,                       -- the artifact link for THIS transition (required on → done; optional elsewhere)
  actor        jsonb NOT NULL,
  at           timestamptz NOT NULL DEFAULT now()
)

board_events (
  id            text PK,                       -- caller-supplied requestId (idempotency key), reconciler-deterministic ids, or minted
  project_id    uuid NOT NULL,
  item_kind     text CHECK ('project','epic','task'),
  item_id       uuid,
  action        text NOT NULL,                 -- BoardService action name (§4.2)
  actor         jsonb NOT NULL,                -- {kind: 'user'|'system', user_id?, surface, claim_token?}
  payload       jsonb,
  created_at    timestamptz NOT NULL,
  UNIQUE (id)                                   -- replay convergence (invariant 4)
)
```

Structural guards: (i) the dependency edge — `board_dependencies` is plain-FK **task→task** (stories do not exist; both endpoints are tasks), with a BEFORE INSERT **trigger** enforcing ruling R4's obligations: same project (cross-epic allowed, cross-project rejected), not self-referential, and **acyclic** — full DFS on insert; a violation is a **409 carrying did-you-mean suggestions** (ruling R4a: suggestions name the near-miss existing tasks — the 0066 helper applied to this 409-class); `PRIMARY KEY (task_id, depends_on_task_id)` makes duplicate edges impossible. (ii) The `epic_id` composite FK guarantees the parent belongs to the *same project*. (iii) **No story-points field, deliberately** (ruling R2) — `board_transitions` carries measured actuals instead; cycle time is an aggregation over the transition log, never an estimate column.

**Blocking — derived, event-driven, materialized (rulings R3/R4).** `is_blocked` has no author: it is **derived** — a task is ready iff `stage='backlog'` **and every dependency target is `done`** (ruling R4: N-ary edges, unblocks when ALL targets Done). The derivation is **materialized** (`is_blocked`) and maintained by the stage-transition handlers in-transaction: `move_stage(→ done)` re-derives each dependent's `is_blocked` (the reverse-edge lookup runs on `board_dependencies(depends_on_task_id)` — instant, event-driven unblocking; a dependent with other non-done dependencies stays blocked); `move_stage(done → anything)` re-blocks; `cancel(…)` stages non-terminal dependents to `pending_input` with reason **"dependency abandoned"** (ruling R4c: an abandoned prerequisite is a human decision — remove the edge, re-point it, or cancel the dependent; the reverse-edge view shows the abandoned edge; note the dependent is NOT silently unblocked: a cancelled dependency is not Done). The reconciler's RC3 pass recomputes `is_blocked` from the edge table as the convergence belt (§4.5). External waits ride all of this for free — "wait for provider fix" is an ordinary task with its own `acceptance_criteria` and `evidence_url`, marked Done by a human when the wait is over, instantly releasing its dependents (ruling R3 consequence 2).

Indexes (all ruling-backed filters): ready-set scan — `tasks (project_id, priority, created_at) WHERE stage='backlog' AND NOT is_blocked` partial (the **stable** predicates only; the time-varying cooldown predicate filters at scan time — an index predicated on `cooldown_until IS NULL` would exclude exactly the post-throttle rows the query must re-serve); reclaim scan — `tasks (lease_expires_at) WHERE stage='in_progress'` partial (pending_input rows are excluded by the stage predicate, §4.4); `(project_id, stage)` on tasks; `board_dependencies (depends_on_task_id)` — the reverse-edge unblock/cascade lookup; `board_transitions (task_id, at)` — cycle-time aggregation; `tags GIN`; `(owner_kind, owner_id, status)` on projects; `board_events (project_id, created_at)` — the SSE replay and reconciler watermark feed.

**Stage semantics** (rulings): `backlog → in_progress → in_review → done` is forward-moving under worker control; **Done = ALL acceptance criteria met + evidence** (ruling R2 — self-defining done): the `move_stage(→ done)` guard requires every criterion's `met` flag set (checked off via `update_task` by the reviewer, optionally with LLM verification assistance surfaced at review — the criteria define Done, they never block) and `evidence_url` present on the `board_transitions` row. Every transition writes its `board_transitions` row (evidence_url per transition, measured timestamps — cycle time is derived from this log, never an estimate column, ruling R2). `pending_input` is enterable from `in_progress`/`in_review`, **from the claim path itself** (the attempts-cap escalation of §4.4 grants no lease — it lands a backlog candidate directly in `pending_input`), and **from cancel** (a cancelled dependency stages its dependents there with "dependency abandoned", §4.1-edges). Three distinct origins with distinct exits: (i) **worker-origin** — the task's worker session has an unanswered question/permission request (the sessionstate pending-input projection is the signal, §4.4); it returns to `in_progress` when resolved, **lease re-armed** by the reconciler at resume (`lease_expires_at = now()+lease`); (ii) **escalated** — attempts ≥ N, no live session; (iii) **dependency-abandoned** — a prerequisite was cancelled; the human resolves the edge (remove or re-point it) or cancels the dependent. For origins (ii) and (iii) alike the exit is a **human `move_stage`** (to `backlog` or `in_progress`), which is the one write that **resets `attempts` to 0** (a human re-queue is a fresh judgment, not another attempt). `cancelled` is terminal and **immutable**: the only legal writes after cancellation are audit/display fields — no stage transition, no reclaim, no resurrect (CHECK-enforced by a `stage_update_guard` trigger that rejects any UPDATE touching `stage` when the old value is `cancelled`, plus the reconciler invariant pin §6). Epic status (`draft/active/paused/completed/archived`, ruling R2) is a lifecycle flag, not a stage machine: `completed` is set by the RC4 sweep when no non-terminal tasks remain; `archived` is reversible storage.

**Display inheritance — materialized at write** (ruling): create/update actions stamp `project_name`/`epic_name`/`tags` onto task rows from the ancestors at write time; filters are plain indexed equality. **Rename = one UPDATE per carrying table**: `UPDATE projects SET name=…` rides in the same transaction as `UPDATE epics SET project_name=… WHERE project_id=…`, and the same single-statement shape for `tasks` (and `epic_name` on epic rename). One statement per table, index-driven `WHERE`, no row loops, no read-modify-write races (the transaction holds the row locks; concurrent item creates serialize on the project row). Tags cascade identically (project tag set changes re-stamp children in the same shape).

**Identifiers** (ruling: reuse the #1691 pattern — i.e. design 0066's machinery, imported, not reinvented): the mint is 0066's (crypto/rand over `[0-9a-z]`, 8 chars, check-and-retry on uniqueness violation, minted in Go never SQL) with the board's prefix table (`prj-`, `epc-`, `tsk-` — no `sty-`: stories do not exist, ruling R1) registered in 0066's closed prefix map. Uniqueness scope: per-project for `epc`/`tsk` (`UNIQUE (project_id, short_id)` — the ruling's "per-project uniqueness"); per-owner for `prj`. Resolution is case-insensitive; **FKs are identity; names/paths are display data** (no references by name anywhere in the schema or API). Did-you-mean 404+suggestions ships on every resolution surface via 0066's generalized helper (candidates = in-scope board short IDs + titles; top-3; suggest-only; 404-class-only — `session_suggest.go:112` discipline), and on the dependency-write 409 per ruling R4a. ### 4.2 BoardService — the one canonical action layer

A single service package (`pkg/board`) owns guards, validation, idempotency, and audit. Every projection (§4.3) is a thin adapter: it authenticates, resolves scope, translates transport to an action call, and renders. **No projection contains business rules.** This is the Epic-64 trigger shape generalized (`triggers.go:4-8`: handlers differ only in owner resolution; here also in claim-token injection).

**Action set** (the ruling's UI action set, expressed as service verbs):

| Action | Guard highlights |
|---|---|
| `create_project` / `update_project` / `archive_project` | authz matrix (§4.7); org-scope create requires an org workspace target (v1) |
| `create_epic` / `update_epic` | project-level authz; status default `draft` |
| `epic_activate` / `epic_pause` | draft/active/paused transitions; activate starts feeding (§4.4); pause stops *new claims*, never interrupts in-flight leases |

| `add_dependency` / `remove_dependency` | rulings R3/R4's only blocking mechanism: N-ary task→task edges within a project (cross-epic allowed), validated by the §4.1 trigger (same-project, no self, no cycle — violations 409 + did-you-mean, R4a); adding/removing re-derives `is_blocked` in-transaction; removing an edge off an abandoned prerequisite is one of the pending_input exits |

**Idempotency** (ruling: "claim tokens + event IDs — outbox clientMessageID discipline"): every mutating action accepts an optional caller-supplied `requestId`; `board_events.id` is that key, written in the same transaction as the effect with the **marker-after-persist** ordering the outbox established (`outbox.go:461-467`): the effect row and event row commit together, a replayed `requestId` hits the `UNIQUE (id)` violation, and the service returns the original event's outcome — **200-with-original, never an error** (`Duplicate{AcceptedID}` contract, `outbox.go:168-173`). The retry contract is stated on the REST/SDK tier the same way the outbox states it for sends: mutating SDK clients **generate one `requestId` per logical operation and reuse it on retry** (clientMessageID discipline verbatim); when a caller supplies none, a unique id is minted and replay protection degrades to that caller alone — the reconciler's own writes always carry deterministic ids (`reconciler:<watermark>:<action>:<item>`, §4.5), so system-side convergence (invariant 4) never depends on caller discipline. Claims additionally carry the one-use **claim token**: stage/lease mutations on an in-flight task by **caller surfaces** require the token held by the caller, so a stale worker (lease reclaimed, re-claimed by another) fails the guard even before authz. The **reconciler is a system actor** (`actor.kind='system'`) and is exempt from the claim-token guard by construction — RC1 reclaims and RC2 drift-writes mutate stage without a token, legitimately; the two named caller-side overrides are `cancel` (revokes the token rather than presenting it) and a human `move_stage` out of escalated `pending_input` (§4.1, which is exactly the lease-free state).

**Audit**: every action writes its `board_events` row (actor incl. surface, action, payload hash) — one audit trail, four surfaces, because there is one service.

### 4.3 Four projections + the parity contract

The parity ruling is pinned as a **contract-test matrix** (§6): rows = every §4.2 action; columns = REST, external MCP (`board_*`), agent-internal MCP (`board_*`); each cell asserts **identical guard outcomes** (allow/deny, error class, idempotent-replay result) against the same fixtures and the same audit row. **(d) Frontend Board UI** (§4.6 of the sketch, spec'd §4.8) — the fourth projection consumes (a) + SSE; it contains no logic the matrix can't reach because every UI gesture maps 1:1 to a §4.2 action.

### 4.4 Dispatch engine — Postgres arbitration, leases, evidence heartbeats, DRR fairness

**No in-memory scheduler state** (ruling). The dispatcher is a pair of SQL statements plus a nudger; any API replica can run the sweep, and Postgres arbitrates every race.

**Atomic claim** (ruling: `UPDATE … WHERE unclaimed RETURNING`). One statement (CTE form), Postgres the only arbiter — the same class as D8's partial-index gate (`000016:270-279`), expressed as claim-guarded UPDATE per #1643's frame:

```sql
WITH p AS (   -- lock the project row: serializes slots/DRR/deficit per project
  SELECT p.id FROM projects p
  WHERE p.id IN (SELECT project_id FROM epics WHERE status='active')  -- active-epic projects, subquery-kept
    AND p.status='active'
    AND (p.slot_cooldown_until IS NULL OR p.slot_cooldown_until < now())
    AND (SELECT count(*) FROM tasks t2
         WHERE t2.project_id = p.id AND t2.stage='in_progress') < p.worker_slots
  ORDER BY p.id FOR UPDATE OF p SKIP LOCKED LIMIT 1
), candidate AS (
  SELECT t.id, t.priority, e.vft, t.created_at FROM tasks t
  JOIN epics e ON e.id = t.epic_id AND e.status='active'
  WHERE t.project_id = (SELECT id FROM p)
    AND t.stage='backlog' AND NOT t.is_blocked
    AND (t.cooldown_until IS NULL OR t.cooldown_until < now())
    AND e.deficit < e.quantum                -- DRR round eligibility (below)
  ORDER BY t.priority ASC, e.vft ASC, t.created_at ASC   -- ready-set order (ruling)
  LIMIT 1 FOR UPDATE OF t SKIP LOCKED
)
UPDATE tasks t SET stage='in_progress', claim_token=gen_random_uuid(),
  assignee_session=:worker, lease_expires_at=now()+:lease, last_progress_at=now(),
  attempts = attempts + 1                    -- the ONLY attempts increment (see below)
FROM candidate c WHERE t.id = c.id
RETURNING t.*;
```

The `p` CTE takes the project row lock first, so the in-flight count against `worker_slots` is read under lock — two concurrent claimers serialize on the project row and the loser's count already includes the winner. The escalation check rides the same transaction: if the top candidate's pre-increment `attempts ≥ N`, the grant is withheld and the task is staged to `pending_input` (escalated, §4.1) instead, returning an `escalated` outcome to the worker (who then claims the next candidate). One transaction, one arbiter, races impossible by construction.

**Deficit round robin** (ruling), mechanically: fairness is per-epic **virtual finish time** bounded by per-epic quanta. On grant, the same transaction runs `UPDATE epics SET vft = vft + 1, deficit = deficit + 1 WHERE id = :epic` (unit cost per claim keeps `vft` globally comparable across projects — it is simply claims served). The candidate predicate `e.deficit < e.quantum` (default `quantum = 1`) skips an epic that has consumed its round allowance until the round completes; **round rollover** is explicit: when the candidate subquery yields no row *because every active epic with ready tasks is at `deficit ≥ quantum`* (the claim returns empty and the sweep's cheap check distinguishes this from an actually-empty ready set), the claimer's transaction resets `deficit = 0` for that project's epics and retries the candidate once. Cross-project fairness composes: `vft` orders all epics globally (work-conserving), each project's claims are capped at `worker_slots` concurrent (the `p` CTE), and `slot_cooldown_until` pauses new claims into a throttled project entirely — so neither a many-epic project nor a hot one starves another. All counters are columns; a crashed dispatcher loses nothing (the next claim recomputes from the same rows); "UI priority changes enter the queue legitimately" because `priority` is read fresh in every claim — the first ORDER BY key.

**attempts — one owner of the increment.** `attempts` counts **claims granted**, and the claim statement above is its *only* increment site. Reclaim (§4.5 RC1) does **not** touch it — a lapsed-and-reclaimed task shows its old count until someone re-claims it, at which point the claim's `attempts+1` lands; the escalation check (pre-increment `attempts ≥ N`) therefore fires on the Nth claim attempt, exactly. The throttle path rolls its own increment back (below): a provider-refused claim was not an attempt. No other write moves the column except the human `move_stage` exit from escalated `pending_input`, which resets it to 0 (§4.1).

**Leases + evidence heartbeats** (rulings: #1643 lease frame + #1685 evidence gating). A claim holds a lease (`lease_expires_at`, default 15 min, tunable like the D6 vars `proxy_lifecycle.go:515-523`). `board_heartbeat(worker, claim_token)` refreshes the lease **only when it carries new progress evidence**: the worker reports its session's event watermark (last message/tool activity), and the service advances `last_progress_at` iff the watermark moved. A heartbeat with no evidence does not extend the lease — this is #1685's ruling made mechanical: *elapsed time is not liveness*; a session streaming/tool-calling for 60 minutes never trips, a silent one trips at one lease window. Pending Input coupling — the component is the **board reconciler** (§4.5): for each task in `in_progress` whose `assignee_session` session has an unanswered question/permission (read from the sessionstate pending-input projection via the internal seam, at sweep cadence), it stages the task to `pending_input`; on resolution it stages it back to `in_progress` **and re-arms the lease** (`lease_expires_at = now()+lease`). The lease never ages out under pending_input by construction — RC1's scan predicate is `stage='in_progress'`, which pending_input is not — and the re-arm closes the spiral where a slow human answer would hand a healthy worker's task to the reclaim path.

**Lease lapse → auto-reclaim** (ruling): the reconciler sweep (§4.5) finds `stage='in_progress' AND lease_expires_at < now()` and reclaims with a guarded UPDATE — `stage='backlog', claim_token=NULL` **and nothing else** (WHERE includes `stage='in_progress'`, so a row cancelled or otherwise moved between scan and UPDATE is a no-op; attempts untouched per above). The next claim increments; **pre-increment `attempts ≥ N → pending_input` escalation** (ruling) happens inside the claim transaction (above) — the task stops being claimable and waits for a human (N default 3, OPEN RULING §8 OR3).

**Provider throttles** (ruling: 429 = cooldown + requeue WITHOUT attempt penalty): `board_report_throttle(claim_token, retry_after)` → one UPDATE: the task returns to `backlog` with `cooldown_until = now()+backoff`, `claim_token=NULL`, and `attempts = attempts - 1` — **rolling back this claim's own increment** (the attempt was provider-refused, not worker-failed; the decrement is exact because report_throttle demands the live token of the claim that incremented). Simultaneously the project's `slot_cooldown_until = now()+backoff` — the worker-slot cooldown's schema home — pausing *new* claims into that project (the `p` CTE predicate) while in-flight leases run their course. The board health panel (§4.8) displays both cooldowns. Platform-level relay backoff is the real fix — the board surfaces health, it does not own provider policy.

**Worker execution model**: a "worker" is a workspace session created by the existing seams — the project's target workspace (`target_workspace_id`), up to `worker_slots` concurrent claims. Claim delivery is pull-with-nudge: the platform pushes a "work available" nudge over `agentpush` when an activate/create unblocks the ready set (log-only failure, exactly the dev-preview-state precedent); the agent's `board_claim_next` does the real arbitration. `task_start` (manual) performs the same claim immediately for one task, valid in draft epics. Worker abort on cancel/reclaim-expiry rides the existing session abort path (the Act `InterruptAction`/abort seam the sessions lane built, `worklogs/0984` D1) — the board never invents a kill mechanism.

### 4.5 Reconciler — convergence sweep, invariants

A single periodic sweep (default 30s; incremental `board_events.created_at` watermark for the drift checks that can be event-fed, plus the two partial-index scans that are cheap by construction):

- **RC1 — lease reclaims**: `stage='in_progress' AND lease_expires_at < now()` → reclaim (§4.4 — stage/`claim_token` only, guarded by `stage='in_progress'`, `attempts` untouched; the increment belongs to the next claim). Invariant-tested (§6, case 1).
- **RC2 — external-truth drift**: tasks carry optional external anchors in `description`/tags (v1: PR references `#N` on the platform's git host). The sweep checks anchored PRs: merged → task `done` (+ the reverse-edge unblock cascade of §4.1-edges), closed-unmerged → task `in_progress` (ruling verbatim — the one backward transition the stage machine enumerates for drift; no `backlog` jump). v1 polls the ref at sweep cadence only for tasks in `in_review` with an anchor — bounded by construction; the anchor extraction is conservative (explicit `pr: N` tag or structured field, never free-text guessing).
- **RC3 — dependency consistency** (rulings R3/R4; the criteria direction is deleted): recompute `is_blocked` from `board_dependencies` — a task is blocked iff ANY dependency target is not `done` (ruling R4's strict ALL-Done semantics) — and repair drift from any missed cascade, the belt beneath the in-transaction §4.1-edges maintenance; plus the abandoned-edge transition class (a dependency that reached `cancelled` while its dependents were non-terminal stages the dependents to `pending_input` with "dependency abandoned", ruling R4c — event-fed on cancel, swept here as the convergence net). No LLM, no prose evaluation, nothing on a cadence slower than the sweep itself.
- **RC4 — epic completion**: an epic with zero non-terminal tasks flips `active → completed` (ruling R2's status set) and stops feeding (its tasks leave the candidate set by the `e.status='active'` guard). Paused/draft epics simply never enter the candidate set; pause never interrupts in-flight leases (they run to completion or lapse normally).
- **RC5 — cancelled immutability**: the reconciler **never** writes to a cancelled item — enforced by the §4.1 trigger (DB-level, belt) and pinned by the §6 case-3 test (braces: a reclaim candidate that was cancelled between scan and UPDATE is a no-op because the **reclaim** UPDATE's WHERE includes `stage='in_progress'` — the scan's own predicate, re-checked at write time — which cancelled is not).

The sweep is idempotent end-to-end: every reconciler write is itself a `board_events` row with a deterministic event ID (`reconciler:<watermark>:<action>:<item>`), so a crash between sweep passes replays to the same state (invariant 4).

### 4.6 SSE live feed

Board events fan out on the existing user + workspace SSE channels (`publishWorkspaceAndUserEvent`, `proxy_lifecycle.go:175`) as `board.event` payloads carrying the `board_events` row (action, item, actor, resulting row-version). Hardening per #1646/#1687: (i) events are **persisted first** (`board_events` is the log; SSE is a projection — the `workspace.alert`+`RecordAlert` pattern, `proxy_lifecycle.go:594-600`); (ii) the frontend board store **reseeds on reconnect** (a `board_read` snapshot fetch on SSE reopen) and **periodically reconciles** (a lightweight version-stamp check), so a silently-dead stream never leaves a stale board — the exact discipline #1687 landed for busy/session state, applied to the board read model; (iii) optimistic UI (drag) applies locally, then the server's authoritative event either confirms or the card **snaps back** (ruling: "optimistic, server-arbitrated snap-back").

## 5. What deliberately does not change

- The harness/session seams: workers are ordinary sessions; the board adds no new execution mechanism (claims nudge + agent MCP; aborts ride the existing interrupt path).
- The trigger/workflow engine — per ruling R5: **workflows are the static-DAG product; the board is the dynamic-backlog product; complementary, not overlapping.** No formal DAG entities, milestones, or phases exist on the board (ruling R5); a board *may* target a workflow in v2 (open), but nothing here touches `engine.go`.
- Design 0066's machinery: imported, not forked — the board registers prefixes in its closed map and reuses mint + suggest helpers.
- The outbox/delivery lane (Epic 71 / #1643 S-stages): board heartbeats *consume* evidence semantics; they add no parallel busy store, no second clock — `last_progress_at` is a board-column watermark, not a session-state input.
- Enumeration posture (#1649-class): every board surface is authenticated + scope-authorized; did-you-mean never suggests across authorization boundaries (0066 §4.7 scoping verbatim).
- The ABI freeze: board traffic is REST/MCP only in v1 — no ABI fields, no pod contract changes (agentd board tools are MCP-over-HTTP via the automation seam, like trigger_*/workflow_*).

## 6. Test strategy (for the implementation lane; red-first there per house rules)

**The four self-healing invariants** (ruling — red-first, one harness each):

1. **Kill worker mid-lease → task reclaims**: claim → kill the worker session → stop heartbeats → advance past `lease_expires_at` (clock seam) → sweep → assert `stage='backlog'`, `claim_token IS NULL`, `attempts` **unchanged** (reclaim never increments); a subsequent `claim_next` increments and grants; with pre-claim `attempts ≥ N` the claim **escalates to `pending_input` instead of granting**; old token now fails `move_stage`.
2. **Merge PR without stage move → converges to Done**: task in `in_review` with `pr:` anchor → merge the PR (fixture host) → ≤ 1 sweep → `stage='done'` + dependents' `is_blocked` re-derived (ready iff ALL dependencies done).
3. **Cancel mid-flight → worker aborted, never resurrects**: claimed task → `cancel` → assert worker session abort issued, token revoked, stage `cancelled`, non-terminal dependents staged `pending_input` ("dependency abandoned"); then run every reconciler path (reclaim scan, drift, dependency consistency) against it → **zero writes** (trigger + pin).
4. **Crash between action and effect → idempotent replay converges**: every mutating action re-invoked with the same `requestId` after simulated mid-transaction death (fault seam) → replay returns 200-with-original, board state converges, exactly one `board_events` row per `requestId`.

**Parity matrix** (ruling: "PARITY IS PINNED"): the §4.3 table-driven contract test — for each (action × surface): allow case, deny case (each guard class), idempotent-replay case, audit-row assertion; declared asymmetries are pinned as **absent-outcome rows**, not missing coverage — worker-only rows (`claim_next`/`heartbeat`/`report_throttle`) assert deny-or-absent on REST/external-MCP, and manager-only rows (CRUD, `cancel`, `add_dependency`/`remove_dependency`, `epic_activate`/`epic_pause`) assert absent on the agent registry (§4.3c).
