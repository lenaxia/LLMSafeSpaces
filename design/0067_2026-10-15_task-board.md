## 1. The problem, in half a page

The platform can run agents (workspaces, sessions, workflows, triggers) but cannot *manage work for them*: an orchestrator's "fix bug X, then review PR Y" lives in a chat transcript, dispatch is ad-hoc (`create_session` + hope), and when a worker dies mid-task nothing reclaims the work. The Task Board adds the missing layer: projects → epics → stories/tasks with stages, an auto-dispatch engine that feeds ready work to worker sessions, and a reconciler that converges board truth when workers die, PRs merge, or operators cancel mid-flight.

Three platform facts make this tractable now rather than novel: (i) the trigger/workflow lane (Epic 64) already established the dual user/org owner model, the REST+MCP parity discipline, and the internal automation seam agentd uses to act on platform objects (`cmd/workspace-agentd/mcp_tools.go:1293`); (ii) design 0066 (PR #1693) built the short-ID mint + did-you-mean machinery the board's identifiers reuse directly; (iii) the #1643/#1685 lanes established that liveness is **evidence, not elapsed time** — the exact semantics a lease/heartbeat engine needs. The board is the composition of these, not a new architecture.

## 2. Settled rulings (owner-approved in #1696 — transcribed verbatim)

> ### Entities & inheritance
> - Projects (swimlane): target workspace, worker count config, tags. Epics per project (default DRAFT; activate → auto-feed work to workers until done; pause stops new claims).
> - Stories (per epic), Tasks (per story or directly per epic). Stages: Backlog → In Progress → In Review → Done + Pending Input (maps to agent.question/permission) + Cancelled (terminal, lease-revoking + worker-abort; reconciler can never resurrect).
> - BLOCKED is orthogonal to stage: item-link (unblocked when target Done) OR natural-language criteria evaluated by LLM (call_with_model, cheap model, on-demand + low-frequency sweep, evidence stored).
> - Display inheritance (materialized at write, rename = one UPDATE): all items carry project name; stories/tasks carry epic name; tags on every entity; indexed filters.
>
> ### Identifiers (reuse #1691 pattern)
> prj-/epc-/sty-/tsk- + 8 chars lowercase+digits, per-project uniqueness, did-you-mean 404+suggestions on every resolution surface. FKs are identity; names/paths are display data.
>
> ### Priority & fairness
> P0–P3 on epics + tasks (default P2). Ready-set order = (priority, virtual_finish_time) — deficit round robin across projects/epics so no epic starves another. UI priority changes enter the queue legitimately.
>
> ### Dispatch engine (self-healing by convergence)
> - Postgres arbitration: atomic claim (UPDATE...WHERE unclaimed RETURNING), no in-memory scheduler state.
> - Leases + heartbeats (reuse #1685 message-level progress evidence); lease lapse → auto-reclaim to Backlog, attempts++; attempts ≥ N → Pending Input escalation.
> - Reconciler sweep (incremental watermark): lease reclaims; external-truth drift (PR merged → Done; closed-unmerged → In Progress); criteria re-eval; epic completion. Cancelled immutable-terminal.
> - Idempotent writes (claim tokens + event IDs — outbox clientMessageID discipline). Provider throttles: 429 = worker-slot cooldown + requeue WITHOUT attempt penalty (platform-level backoff is the real fix, board displays health).
>
> ### Surface model — ONE canonical action layer, four projections
> All guards/validation/idempotency/audit live once in BoardService. Projections: (a) REST for UI + SDKs (openapi canonical, 4 SDKs, canaries, freeze gate, BREAKING discipline — full product contract tier); (b) EXTERNAL platform MCP server (customer-facing board.* tools, same handlers, customer authz); (c) agent-internal MCP registry (agentd/origin-plugin pattern; adds claim-token semantics); (d) frontend Board UI beside Triggers/Workflows.
> - UI action set (parity across ALL surfaces): drag=move_stage (optimistic, server-arbitrated snap-back), PATCH item, task:start (manual one-off dispatch even in draft epics), epic:activate/pause, cancel (task/story/epic), CRUD, board read model + SSE live feed.
> - PARITY IS PINNED: contract-test matrix asserting every action expressible via REST + both MCP registries with identical guard outcomes.
>
> ### Authz (dual granularity)
> owner_kind: user|org on projects (cascades). User-scope: private boards, personal workspaces. Org-scope: role-gated (owner/admin full; member matrix = OPEN RULING), org workspaces only (v1). Workers delegate as their user; claim tokens are the in-flight guard. UI scope switcher Personal | <Org>.
>
> ### Frontend
> Kanban: columns=stages, swimlanes=projects; epic chips, tag filters, search with did-you-mean. Cards: short ID, priority, tags, blocked badge (+Evaluate-now), assignee busy indicator (the #1687-hardened one), attempt counter. Epic drawer: progress, activate/pause, worker budget, SSE activity feed. Health panel: leases, reclaims, cooldowns, pending criteria evals.
>
> ### Self-healing test invariants (red-first lane discipline)
> Kill worker mid-lease → task reclaims. Merge PR without stage move → converges to Done. Cancel mid-flight → worker aborted, never resurrects. Crash between action and effect → idempotent replay converges.

## 4. The design

### 4.1 Entity model, schema, migrations

One migration (`000036_task_board.up/.down`), four tables plus an event log, following the 000016 conventions (CHECK constraints inline, `DO $$` constraint creation, partial indexes, `update_updated_at` triggers).

```
projects (
  id            uuid PK,
  short_id      text NOT NULL,                 -- prj-XXXXXXXX
  owner_kind    text NOT NULL CHECK ('user','org'),
  owner_id      text NOT NULL,                 -- user id or org id
  name          text NOT NULL,
  target_workspace_id uuid REFERENCES workspaces(id),   -- v1: single target (§8 R2)
  worker_slots  int NOT NULL DEFAULT 2,        -- max concurrent in-flight claims
  tags          text[] NOT NULL DEFAULT '{}',
  status        text NOT NULL DEFAULT 'active' CHECK ('active','archived'),
  created_at/updated_at,
  UNIQUE (owner_kind, owner_id, short_id)
)

epics (
  id            uuid PK,
  project_id    uuid NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
  short_id      text NOT NULL,                 -- epc-XXXXXXXX
  title         text NOT NULL,
  description   text NOT NULL DEFAULT '',
  status        text NOT NULL DEFAULT 'draft' CHECK ('draft','active','paused','done'),
  priority      text NOT NULL DEFAULT 'P2' CHECK ('P0','P1','P2','P3'),
  -- display inheritance, materialized (ruling):
  project_name  text NOT NULL,
  tags          text[] NOT NULL DEFAULT '{}',
  -- DRR state (per-epic virtual clock; Postgres is the only state, §4.4):
  vft           bigint NOT NULL DEFAULT 0,     -- virtual finish time, monotonically advancing
  deficit       bigint NOT NULL DEFAULT 0,     -- DRR deficit counter
  created_at/updated_at,
  UNIQUE (project_id, short_id)
)

stories (
  id            uuid PK,
  project_id    uuid NOT NULL REFERENCES projects(id) ON DELETE CASCADE,  -- denormalized: uniqueness scope + inheritance
  epic_id       uuid NOT NULL REFERENCES epics(id) ON DELETE CASCADE,
  short_id      text NOT NULL,                 -- sty-XXXXXXXX
  title, description,
  stage         text NOT NULL DEFAULT 'backlog' CHECK ('backlog','in_progress','in_review','done','pending_input','cancelled'),
  priority      text NOT NULL DEFAULT 'P2',
  project_name  text NOT NULL, epic_name text NOT NULL, tags text[],
  -- blocked (orthogonal to stage, ruling):
  blocked_kind  text NOT NULL DEFAULT 'none' CHECK ('none','item','criteria'),
  blocked_target_id uuid REFERENCES board-eligible items (stories/tasks, deferrable),  -- item-link
  blocked_criteria  text,                      -- NL criteria (kind='criteria')
  blocked_eval jsonb,                          -- last evaluation evidence {verdict, model, rationale, evaluated_at}
  created_at/updated_at,
  UNIQUE (project_id, short_id)
)

tasks (
  id            uuid PK,
  project_id    uuid NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
  epic_id       uuid NOT NULL REFERENCES epics(id) ON DELETE CASCADE,
  story_id      uuid NULL REFERENCES stories(id) ON DELETE CASCADE,   -- NULL ⇒ epic-level task
  short_id      text NOT NULL,                 -- tsk-XXXXXXXX
  title, description,                          -- description = the work prompt handed to a worker
  stage, priority, project_name, epic_name, tags, blocked_*  -- as stories; stories additionally carry story_id in list projections
  -- dispatch state (Postgres-arbitrated, §4.4):
  claim_token   uuid NULL,                     -- set while claimed; the in-flight guard
  claimed_by    text NULL,                     -- worker identity: workspace_id + session_short_id
  lease_expires_at timestamptz NULL,
  last_evidence_at timestamptz NULL,           -- evidence-bearing heartbeat watermark (§4.4)
  attempts      int NOT NULL DEFAULT 0,
  cooldown_until timestamptz NULL,             -- provider-throttle slot cooldown

board_events (
  id            text PK,                       -- caller-supplied event ID (idempotency key) or minted
  project_id    uuid NOT NULL,
  item_kind     text CHECK ('project','epic','story','task'),
  item_id       uuid,
  action        text NOT NULL,                 -- BoardService action name (§4.6)
  actor         jsonb NOT NULL,                -- {user_id, surface, claim_token?}
  payload       jsonb,
  created_at    timestamptz NOT NULL,
  UNIQUE (id)                                   -- replay convergence (invariant 4)

```

Indexes (all ruling-backed filters): `(project_id, stage)` on tasks; `(project_id, stage='backlog') WHERE blocked_kind='none' AND cooldown_until IS NULL` partial — the ready-set scan; `lease_expires_at WHERE stage='in_progress'` partial — the reclaim scan; `blocked_target_id WHERE blocked_kind='item'` — unblock-on-done cascade lookup; `tags GIN`; `(owner_kind, owner_id, status)` on projects; `board_events (project_id, created_at)` — the SSE replay and reconciler watermark feed.

**Stage semantics** (ruling): `backlog → in_progress → in_review → done` is forward-moving under worker control; `pending_input` is enterable from `in_progress`/`in_review` and maps 1:1 to the platform's existing agent question/permission surfaces (a task enters Pending Input when its worker's session has an unanswered question/permission request; it returns to In Progress when resolved — reusing the sessionstate pending-input projection as the signal, §4.4); `cancelled` is terminal and **immutable**: the only legal writes after cancellation are audit/display fields — no stage transition, no reclaim, no resurrect (CHECK-enforced by a `stage_update_guard` trigger that rejects any UPDATE touching `stage` when the old value is `cancelled`, plus the reconciler invariant pin §6).

**Display inheritance — materialized at write** (ruling): create/update actions stamp `project_name`/`epic_name`/`tags` onto every child row from the ancestor at write time; filters are plain indexed equality. **Rename = one UPDATE per carrying table**: `UPDATE projects SET name=…` rides in the same transaction as `UPDATE epics SET project_name=… WHERE project_id=…`, and the same single-statement shape for `stories`/`tasks` (and `epic_name` on rename). One statement per table, index-driven `WHERE`, no row loops, no read-modify-write races (the transaction holds the row locks; concurrent item creates serialize on the project row). Tags cascade identically (project tag set changes re-stamp children in the same shape).

**Identifiers** (ruling: reuse the #1691 pattern — i.e. design 0066's machinery, imported, not reinvented): the mint is 0066's (crypto/rand over `[0-9a-z]`, 8 chars, check-and-retry on uniqueness violation, minted in Go never SQL) with the board's prefix table (`prj-`, `epc-`, `sty-`, `tsk-`) registered in 0066's closed prefix map. Uniqueness scope: per-project for `epc/sty/tsk` (`UNIQUE (project_id, short_id)` — the ruling's "per-project uniqueness"); per-owner for `prj`. Resolution is case-insensitive; **FKs are identity, names are display data** (no references by name anywhere in the schema or API). Did-you-mean 404+suggestions ships on every resolution surface via 0066's generalized helper (candidates = in-scope board short IDs + titles; top-3; suggest-only; 404-class-only — `session_suggest.go:112` discipline). Dependency note: this is why the implementation lane sequences behind PR #1693 (§7) — the board imports its mint + suggest library rather than forking it.

### 4.2 BoardService — the one canonical action layer

A single service package (`pkg/board`) owns guards, validation, idempotency, and audit. Every projection (§4.3) is a thin adapter: it authenticates, resolves scope, translates transport to an action call, and renders. **No projection contains business rules.** This is the Epic-64 trigger shape generalized (`triggers.go:4-8`: handlers differ only in owner resolution; here also in claim-token injection).

**Action set** (the ruling's UI action set, expressed as service verbs):

| Action | Guard highlights |
|---|---|
| `create_project` / `update_project` / `archive_project` | authz matrix (§4.7); org-scope create requires an org workspace target (v1) |
| `create_epic` / `update_epic` | project-level authz; status default `draft` |
| `epic_activate` / `epic_pause` | draft/active/paused transitions; activate starts feeding (§4.4); pause stops *new claims*, never interrupts in-flight leases |
| `create_story` / `update_story` | epic must not be cancelled/done |
| `create_task` / `update_task` (`PATCH item` — title, description, priority, tags, assignee hints) | priority changes are ordinary writes — "UI priority changes enter the queue legitimately": the dispatcher reads priority fresh each claim; there is no cached order to invalidate |
| `move_stage` | stage-machine guards (§4.1); **server-arbitrated**: optimistic UI, but the service is the arbiter — a drag that loses a race (item reclaimed, cancelled, or lease-held by another) returns the authoritative row and the UI snaps back |
| `task_start` | manual one-off dispatch — **explicitly allowed in draft epics** (ruling); performs an immediate claim bypass for one task without activating the epic |
| `cancel` (task/story/epic) | terminal write: revokes lease (clears claim token), issues worker abort (§4.4), cascades to descendants (story → its tasks; epic → stories+tasks; already-`done` descendants stay done, non-terminal descendants become `cancelled`) |
| `set_blocked` / `clear_blocked` | item-link (target must be a board item in scope) or NL criteria; `Evaluate-now` = `evaluate_criteria` on demand |
| `evaluate_criteria` | LLM evaluation via `call_with_model` semantics — cheap model, evidence stored to `blocked_eval` (§4.5) |
| `claim_next` | dispatch-engine entry (§4.4); worker-surface only (agent MCP / internal seam) |
| `heartbeat` | evidence-bearing (§4.4); requires matching claim token |
| `report_throttle` | 429 path (§4.4): requeue without attempt penalty + slot cooldown |
| `board_read` (list/get/search/health) | read model over the materialized columns; the SSE feed is a read projection (§4.5) |

**Idempotency** (ruling: "claim tokens + event IDs — outbox clientMessageID discipline"): every mutating action accepts an optional caller-supplied `requestId`; `board_events.id` is that key, written in the same transaction as the effect with the **marker-after-persist** ordering the outbox established (`outbox.go:461-467`): the effect row and event row commit together, a replayed `requestId` hits the `UNIQUE (id)` violation, and the service returns the original event's outcome — **200-with-original, never an error** (`Duplicate{AcceptedID}` contract, `outbox.go:168-173`). Claims additionally carry the one-use **claim token**: stage/lease mutations on an in-flight task require the token held by the caller, so a stale worker (lease reclaimed, re-claimed by another) fails the guard even before authz.

**Audit**: every action writes its `board_events` row (actor incl. surface, action, payload hash) — one audit trail, four surfaces, because there is one service.

### 4.3 Four projections + the parity contract

The parity ruling is pinned as a **contract-test matrix** (§6): rows = every §4.2 action; columns = REST, external MCP (`board_*`), agent-internal MCP (`board_*`); each cell asserts **identical guard outcomes** (allow/deny, error class, idempotent-replay result) against the same fixtures and the same audit row. The matrix is generated from one table-driven spec (action × surface × case), so adding an action without adding its surface rows fails the build — parity by construction, the `triggers_test.go` + D5-parity-pin discipline (`worklogs/0984`) promoted to the tier template.

**(a) REST — full product contract tier.** Routes mirror Epic 64's dual-scope shape (`router.go:2102-2121`):

- `/api/v1/me/projects[/:projectId[/epics|stories|tasks…]]` — user-scope board (AuthMiddleware; owner resolves to the JWT user).
- `/api/v1/orgs/:orgId/projects[...]` — org-scope board (AuthMiddleware + org-role middleware per §4.7; **not** blanket OrgAdminGuard — members act on boards, the matrix rules how).
- Item-addressing routes take short IDs (`prj-…/epc-…/sty-…/tsk-…`), resolved case-insensitively with did-you-mean 404s.
- `sdks/openapi.yaml` is canonical; 4 SDKs, canaries, freeze gate, BREAKING discipline — additive-only until a major, exactly the workflow/trigger tier.

**(b) External platform MCP server.** `pkg/mcp/board_tools.go` beside `workflow_tools.go`, registered by `AddBoardTools(srv, h)` in `NewServer` (`server.go:47-48` pattern). Tools: `board_list_projects`, `board_get`, `board_create_*`, `board_update_item`, `board_move_stage`, `board_start_task`, `board_epic_activate/pause`, `board_cancel`, `board_set_blocked`, `board_evaluate_criteria`, `board_read` (list/search). Handlers call the same BoardService with customer authz (§4.7) — no claim/heartbeat here: claiming is a worker activity and lives on the agent surface only. (Deliberate asymmetry, mirrored in the matrix as "agent-only": rows `claim_next`/`heartbeat`/`report_throttle` assert deny-or-absent on REST/external-MCP.)

**(c) Agent-internal MCP registry** (the origin-plugin/`mcpAutomation` pattern, `mcp_tools.go:1293-1347`): agentd exposes `board_claim_next`, `board_heartbeat`, `board_report_throttle`, `board_move_stage`, `board_read`, `board_start_task`, `board_evaluate_criteria` to the in-workspace agent; each calls the platform's internal automation seam (`/internal/v1/automation/board/*`, router group beside `router.go:1302/1311`) with the pod SA token, body passed through verbatim — "the platform validates". This projection **adds claim-token semantics**: `board_claim_next` returns the token; `board_move_stage`/`board_heartbeat` on an in-flight task require it (§4.2). Worker identity = the workspace's owning user ("workers delegate as their user"); the pod SA token is that user's delegation, so authz resolves through the same §4.7 matrix with the worker's user identity, and the claim token is the in-flight guard above it.

**(d) Frontend Board UI** (§4.6 of the sketch, spec'd §4.8) — the fourth projection consumes (a) + SSE; it contains no logic the matrix can't reach because every UI gesture maps 1:1 to a §4.2 action.

### 4.4 Dispatch engine — Postgres arbitration, leases, evidence heartbeats, DRR fairness

**No in-memory scheduler state** (ruling). The dispatcher is a pair of SQL statements plus a nudger; any API replica can run the sweep, and Postgres arbitrates every race.

**Atomic claim** (ruling: `UPDATE … WHERE unclaimed RETURNING`):

```sql
WITH candidate AS (
  SELECT t.id FROM tasks t
  JOIN epics e ON e.id = t.epic_id AND e.status = 'active'
  WHERE t.project_id = ANY(:active_projects)
    AND t.stage = 'backlog' AND t.blocked_kind = 'none'
    AND (t.cooldown_until IS NULL OR t.cooldown_until < now())
  ORDER BY t.priority ASC, e.vft ASC, t.created_at ASC   -- ready-set order (ruling)
  LIMIT 1
  FOR UPDATE OF t SKIP LOCKED
)
UPDATE tasks t SET stage='in_progress', claim_token=gen_random_uuid(),
  claimed_by=:worker, lease_expires_at=now()+:lease, last_evidence_at=now(), attempts=attempts+1
FROM candidate c WHERE t.id = c.id
RETURNING t.*;
```

One statement, one arbiter, races impossible by construction — the same class as D8's partial-index gate (`000016:270-279`), expressed as claim-guarded UPDATE per #1643's frame. After a successful claim the winner advances the epic's `vft` and project deficit counters (one follow-up UPDATE in the same transaction).

**Deficit round robin** (ruling): fairness is per-epic **virtual finish time** with per-project deficit caps. When epic E's task is claimed: `E.vft += 1` (a unit of virtual service) and E accrues deficit against its project's per-epic quantum; an epic that has consumed its quantum in the current round is skipped in the candidate ORDER BY until the round completes (its `vft` has advanced past peers), so a 10-epic project cannot starve a 1-epic project *within* a project, and across projects the per-project `worker_slots` bound caps concurrent claims. All counters are columns; a crashed dispatcher loses nothing (next claim recomputes from the same rows); "UI priority changes enter the queue legitimately" because `priority` is read fresh in every claim — the first ORDER BY key.

**Leases + evidence heartbeats** (rulings: #1643 lease frame + #1685 evidence gating). A claim holds a lease (`lease_expires_at`, default 15 min, tunable like the D6 vars `proxy_lifecycle.go:515-523`). `board_heartbeat(worker, claim_token)` refreshes the lease **only when it carries new progress evidence**: the worker reports its session's event watermark (last message/tool activity), and the service advances `last_evidence_at` iff the watermark moved. A heartbeat with no evidence does not extend the lease — this is #1685's ruling made mechanical: *elapsed time is not liveness*; a session streaming/tool-calling for 60 minutes never trips, a silent one trips at one lease window. Pending Input coupling: while a claimed task's worker session has an unanswered question/permission (sessionstate pending-input projection, the `lease.go` diff surface), the task auto-stages to `pending_input` and the lease clock **pauses** (a human owes an answer; that is not a worker failure) — resuming on resolution back to `in_progress`.

**Lease lapse → auto-reclaim** (ruling): the reconciler sweep (§4.5) finds `stage='in_progress' AND lease_expires_at < now()` and atomically reclaims: stage→`backlog`, `claim_token=NULL`, `attempts+1` (the claim already incremented on re-claim per the SQL above; attempts counts *claims*, one increment at claim time — reclaim itself does not double-count). **attempts ≥ N → Pending Input escalation** (ruling): the task stages to `pending_input` with a system note "escalated after N attempts", stops being claimable, and waits for a human (N default 3, OPEN RULING §8 R3).

**Provider throttles** (ruling: 429 = cooldown + requeue WITHOUT attempt penalty): `board_report_throttle(claim_token, retry_after)` → the task returns to `backlog` with `cooldown_until = now()+backoff`, the worker's project slot enters cooldown, and **attempts is decremented** (the attempt was provider-refused, not worker-failed — mechanically: attempts is not incremented at claim for a throttle-reported claim; simplest consistent shape: report_throttle rolls the increment back). The board health panel (§4.8) displays active cooldowns. Platform-level relay backoff is the real fix — the board surfaces health, it does not own provider policy.

**Worker execution model**: a "worker" is a workspace session created by the existing seams — the project's target workspace (`target_workspace_id`), up to `worker_slots` concurrent claims. Claim delivery is pull-with-nudge: the platform pushes a "work available" nudge over `agentpush` when an activate/create unblocks the ready set (log-only failure, exactly the dev-preview-state precedent); the agent's `board_claim_next` does the real arbitration. `task_start` (manual) performs the same claim immediately for one task, valid in draft epics. Worker abort on cancel/reclaim-expiry rides the existing session abort path (the Act `InterruptAction`/abort seam the sessions lane built, `worklogs/0984` D1) — the board never invents a kill mechanism.

### 4.5 Reconciler — convergence sweep, invariants

A single periodic sweep (default 30s; incremental `board_events.created_at` watermark for the drift checks that can be event-fed, plus the two partial-index scans that are cheap by construction):

- **R1 — lease reclaims**: `stage='in_progress' AND lease_expires_at < now()` → reclaim (§4.4). Invariant-tested (§6, case 1).
- **R2 — external-truth drift**: tasks carry optional external anchors in `description`/tags (v1: PR references `#N` on the platform's git host). The sweep checks anchored PRs: merged → task `done` (+ item-link unblock cascade), closed-unmerged → task back to `in_progress`/`backlog` (ruling). v1 polls the ref at sweep cadence only for tasks in `in_review` with an anchor — bounded by construction; the anchor extraction is conservative (explicit `pr: N` tag or structured field, never free-text guessing).
- **R3 — criteria re-eval** (ruling: on-demand + low-frequency sweep): `blocked_kind='criteria'` items re-evaluate at low frequency (default: hourly sweep + on-demand `Evaluate-now`), via a cheap `call_with_model`-shaped LLM call whose **evidence is stored** (`blocked_eval`: verdict, model, rationale, evaluated_at — the ruling's "evidence stored"); verdict=unblocked → `blocked_kind='none'` and the item re-enters the ready set. Item-link blocks unblock when the target hits `done` (event-fed: the `move_stage(done)` handler runs the `blocked_target_id` lookup in-transaction — no sweep needed for the common case).
- **R4 — epic completion**: an epic with zero non-terminal descendants flips `active → done` and stops feeding (its tasks leave the candidate set by the `e.status='active'` guard). Paused/draft epics simply never enter the candidate set; pause never interrupts in-flight leases (they run to completion or lapse normally).
- **R5 — cancelled immutability**: the reconciler **never** writes to a cancelled item — enforced by the §4.1 trigger (DB-level, belt) and pinned by the §6 case-3 test (braces: a reclaim candidate that was cancelled between scan and UPDATE is a no-op because the claim UPDATE's WHERE includes `stage='backlog'`, which cancelled is not).

The sweep is idempotent end-to-end: every reconciler write is itself a `board_events` row with a deterministic event ID (`reconciler:<watermark>:<action>:<item>`), so a crash between sweep passes replays to the same state (invariant 4).

### 4.6 SSE live feed

Board events fan out on the existing user + workspace SSE channels (`publishWorkspaceAndUserEvent`, `proxy_lifecycle.go:175`) as `board.event` payloads carrying the `board_events` row (action, item, actor, resulting row-version). Hardening per #1646/#1687: (i) events are **persisted first** (`board_events` is the log; SSE is a projection — the `workspace.alert`+`RecordAlert` pattern, `proxy_lifecycle.go:594-600`); (ii) the frontend board store **reseeds on reconnect** (a `board_read` snapshot fetch on SSE reopen) and **periodically reconciles** (a lightweight version-stamp check), so a silently-dead stream never leaves a stale board — the exact discipline #1687 landed for busy/session state, applied to the board read model; (iii) optimistic UI (drag) applies locally, then the server's authoritative event either confirms or the card **snaps back** (ruling: "optimistic, server-arbitrated snap-back").

### 4.7 Authz — dual granularity

**`owner_kind` user|org on projects, cascading** (ruling): every descendant authorization resolves up to the project. The model reuses the Epic-64 dual-scope machinery verbatim (`triggers.go` owner resolution + the me/org route pairs), with `org_memberships` roles (`admin|member`, initial schema `:230-236`) as the org-side lattice and the org **owner** (first-admin) above it.

| Capability | user-scope (owner) | org owner | org admin | org member | worker (delegated user) |
|---|---|---|---|---|---|
| CRUD projects/epics/stories/tasks | ✔ (own boards) | ✔ | ✔ | **OPEN RULING R1** (proposed: create/update tasks ✔; create/delete epics/projects ✘) | via R1 as their user |
| epic activate/pause, cancel | ✔ | ✔ | ✔ | **R1** (proposed: ✘) | ✘ (except own-claimed task via claim token) |
| move_stage | ✔ | ✔ | ✔ | **R1** (proposed: tasks ✔, story/epic stage ✘) | own claimed task only (claim token) |
| task_start (manual dispatch) | ✔ | ✔ | ✔ | **R1** (proposed: ✔) | ✔ (it's a claim) |
| claim_next / heartbeat / report_throttle | — (not worker) | — | — | — | ✔ (worker surfaces; claim token guards) |
| board_read / health | ✔ | ✔ | ✔ | ✔ | ✔ within scope |
| evaluate_criteria | ✔ | ✔ | ✔ | ✔ (on-demand) | ✔ |

**Workers delegate as their user; claim tokens are the in-flight guard** (ruling): the pod SA token resolves to the workspace's owning user (§4.3c); board authz evaluates that user against the project's owner scope (a personal workspace's user must own/have access to the project — org projects targeting org workspaces means workers are org members acting under R1's worker row). The claim token then narrows in-flight writes to the holder: no user, however privileged, accidentally trips a stale worker's lease because stage/lease writes demand the token; privileged overrides (cancel) explicitly revoke the token instead.

**v1 targeting: org workspaces only** (ruling, OPEN RULING R2 to confirm breadth): an org-scope project's `target_workspace_id` must reference a workspace with the same `org_id`; user-scope projects target that user's personal workspaces. The create/update guard is a single FK-shape check (§3).

**UI scope switcher `Personal | <Org>`**: the frontend board page carries the same scope switcher the org surfaces establish — it selects which route prefix (a) the reads/writes use; no cross-scope queries exist (the API is scoped by route, so the switcher is pure routing, not a filter).

## 5. What deliberately does not change

- The harness/session seams: workers are ordinary sessions; the board adds no new execution mechanism (claims nudge + agent MCP; aborts ride the existing interrupt path).
- The trigger/workflow engine: boards are a sibling plane, not a workflow replacement; a board *may* target a workflow in v2 (open), but nothing here touches `engine.go`.
- Design 0066's machinery: imported, not forked — the board registers prefixes in its closed map and reuses mint + suggest helpers.
- The outbox/delivery lane (Epic 71 / #1643 S-stages): board heartbeats *consume* evidence semantics; they add no parallel busy store, no second clock — `last_evidence_at` is a board-column watermark, not a session-state input.
- Enumeration posture (#1649-class): every board surface is authenticated + scope-authorized; did-you-mean never suggests across authorization boundaries (0066 §4.7 scoping verbatim).
- The ABI freeze: board traffic is REST/MCP only in v1 — no ABI fields, no pod contract changes (agentd board tools are MCP-over-HTTP via the automation seam, like trigger_*/workflow_*).

## 6. Test strategy (for the implementation lane; red-first there per house rules)

**The four self-healing invariants** (ruling — red-first, one harness each):

1. **Kill worker mid-lease → task reclaims**: claim → kill the worker session → stop heartbeats → advance past `lease_expires_at` (clock seam) → sweep → assert `stage='backlog'`, `claim_token IS NULL`, `attempts` incremented; old token now fails `move_stage`.
2. **Merge PR without stage move → converges to Done**: task in `in_review` with `pr:` anchor → merge the PR (fixture host) → ≤ 1 sweep → `stage='done'` + linked blocked item unblocked.
3. **Cancel mid-flight → worker aborted, never resurrects**: claimed task → `cancel` → assert worker session abort issued, token revoked, stage `cancelled`; then run every reconciler path (reclaim scan, drift, re-eval) against it → **zero writes** (trigger + pin).
4. **Crash between action and effect → idempotent replay converges**: every mutating action re-invoked with the same `requestId` after simulated mid-transaction death (fault seam) → replay returns 200-with-original, board state converges, exactly one `board_events` row per `requestId`.

**Parity matrix** (ruling: "PARITY IS PINNED"): the §4.3 table-driven contract test — for each (action × surface): allow case, deny case (each guard class), idempotent-replay case, audit-row assertion; agent-only rows assert deny/absent elsewhere. CI fails on any action lacking full surface coverage.

**Engine**: concurrent `claim_next` race (N workers × 1 ready task → exactly one winner, losers get empty-or-next); DRR starvation pin (two epics, one aggressive — neither starves across K rounds); priority-respected-first pin; cooldown exclusion; throttle requeue leaves `attempts` unchanged; heartbeat evidence gate (watermark-moved extends lease; silent heartbeat does not); pending-input lease pause/resume.

**Reconciler**: watermark incrementality (no rescan); R2 both drift directions; R3 evidence payload shape + unblock transition; R4 epic completion stops feeding; R5 immutability (above).

**Authz**: the §4.7 matrix as executable table tests per surface (the matrix *is* the test cases); worker-delegation resolution (SA token → user → R1 row); claim-token guard negative space.

**Contract tier**: openapi additive-only freeze pins, 4-SDK canaries, REST schema tests — the Epic-64 gate applied to board routes.

**SSE**: persist-then-publish ordering pin; reconnect-reseed integration (frontend vitest, #1687 pattern); optimistic snap-back arms.
