**Status:** Proposed (2026-09-28) — design stage; adoption is NOT requested. This document records evidence and stages a path; implementation stories follow owner approval of a specific stage, not of this document as a whole.
**Date:** 2026-09-28
**Issues:** #1595 (this lane) · #730 (the golden-fixture drift tax, Sev1 history outage) · #1582 (consent flow) — read in full.
**Elaborates:** design 0049 (the agent session contract and its five part types), design/stories/epic-65-agent-session-contract (US-65.4 history, US-65.8 adapter SSE), design 0062 (PR #1585, pending merge at time of writing — cited for its decision *pattern*: choosing the surface whose stability the counterparty has committed to, rather than one we must re-verify every bump).
**Spike artifacts:** `design/evidence/acp-spike/` — four drivers (`acp_drive.mjs`, `acp_silentignore.mjs`, `acp_lifecycle.mjs`, `fork.mjs`), seven verbatim transcripts (`transcript-{ping2,tools2,perm3,editperm,silentignore,lifecycle,fork}.ndjson`, every message in both directions with full payloads, timestamped), the two playground `opencode.json` ask-configs (`playground-config/`), and `binary-zod-extract.md` (the schema excerpts from the pinned binary that back every `[zod]` citation, with extraction provenance). ## 1. The question and the answer in one page

**Question (#1595):** opencode's native HTTP/history/SSE surface promises nothing across upgrades — #730 proved a minor bump (1.18.4→1.18.10) can reshape it under us (502 on every history call, fleet-wide). The platform pays a standing tax: per-version golden captures (`testdata/golden/sse_events_1_18_{10,15}_live_abi.want.jsonl`), a hand-maintained event dialect (`dialect.go`), and a 1,000-line translation layer (`translate.go`). opencode also ships `opencode acp` — a first-class JSON-RPC/stdio server that exists *for external clients*, which is the strongest stability commitment an upstream can make short of a contract. Should we consume it?

**Answer:** ACP is viable, maps cleanly onto the five contract part types with **zero part-type changes**, and retires the most fragile half of the drift tax (SSE event shapes, permission dialect). It does **not** cover agent configuration (ConfigWriter stays), and its own spec maturity is a real but bounded risk (§7). The staged path: **(a)** adopt ACP *shapes* in the adapter's SSE bridge now (no transport change, retires nothing yet but freezes the contract-side vocabulary); **(b)** transport migration (stdio pipes replacing `opencode serve` HTTP) is a bounded, separately-gated change assessed in §6; **(c)** full adoption triggers are named in §6.3 and neither has fired.

The headline evidence: one permission round-trip, captured verbatim (§4.3) — including a committed transcript of the failure mode: a malformed consent response is **silently ignored**, wedging the turn until cancelled (§5.1) — replaces the entire `per_`/`/permission/{id}/reply` dialect with a typed, versioned request/response pair. The spike also found a divergence set between opencode's ACP and both its own bundled library and the public spec drafts (§5), which is exactly the class of finding that justifies a spike before a design.

## 2. How the spike was run

Pinned binary `/opencode/usr/local/bin/opencode` = **1.18.15** (`--version` verified), spawned as `opencode acp --pure --cwd <scratch>` with newline-delimited JSON-RPC over stdio from node drivers in `/tmp/opencode/acpspike/` (no pod changes; read-only protocol archaeology). **Twelve protocol runs across twelve scratch cwds; seven transcripts committed** — the operative evidence for every claim in this doc. Committed set: `ping2` (minimal turn), `tools2` (write+bash under default-allow), `perm3` (bash permission under an `ask` playground config), `editperm` (write-tool **edit/diff** permission under `ask` — the §4.3 centerpiece), `silentignore` (the §5.1 wedge capture: wrong-shape consent response → stall → notification-cancel → recovery → correct-shape grant), `lifecycle` (list/set_config_option/set_model/fork-error/load), `fork` (fork-with-cwd + load, full-payload logging — the §3.2 `user_message_chunk` replay evidence). The five uncommitted runs were superseded driver iterations (a wrong-method-name ping; a no-config tools run; three consent-shape ladder attempts invalidated by the duplicate-response-id flaw — one fresh request per tested shape is the valid method, which is what `silentignore` captures). The `ask` configs are committed under `playground-config/`. Static cross-check: `binary-zod-extract.md` (extraction command + verbatim schema excerpts from the binary) — cited below as **[zod]** alongside live **[T:<label>]** citations.

Everything in §3–§4 marked **live** was observed on the wire in a committed transcript; everything marked **[zod]** exists in the binary's schema (committed extract) but was not emitted by opencode's adapter in any run.

## 4. The mapping table (centerpiece)

### 4.1 ContentBlock → part content

| ACP ContentBlock | Contract (0049) |
|---|---|
| `{type:"text", text}` | `Text` part body |
| `{type:"image", data, mimeType}` | `Tool` output (screenshot discipline — 0049 §"Deliberately NOT part types") |
| `{type:"audio"}` / `{type:"resource_link"}` / `{type:"resource"}` | `Custom` (kind `acp.resource`) — none observed live; capability-gated by `promptCapabilities` |

### 4.2 Streaming → parts

| ACP stream event | Contract part | State machine note |
|---|---|---|
| `agent_message_chunk` | `Text` append | same accumulation we do for `message.part.delta` today |
| `agent_thought_chunk` | `Reasoning` append | |
| `tool_call` (status pending) | `Tool` create, state `pending` | |
| `tool_call_update` (in_progress) | `Tool` → `running` | rawInput enrich (command/title fill in progressively — observed live) |
| `tool_call_update` (completed/failed) | `Tool` → `completed|error`, output from `content[]` + `rawOutput` | |
| `tool_call_update.content[{type:"diff"}]` | **`FileChange`** (structured oldText/newText per file — exactly the 0049 shape; also arrives inside the permission request, §4.3) | |
| `plan` (if ever emitted) | `Tool` name=`todowrite`-class — **not** a new part type | 0049 discipline §3 ("all tools are ToolPart, forever") |
| `available_commands_update` | `Custom` kind=`acp.available_commands` (frontend already renders command menus) | |
| `usage_update` | session-level context gauge (existing `ContextUsage` wiring, #940) — not a part | |
| `user_message_chunk` (replay-only, §3.2) | user-turn `Text` part on fork/load history ingestion — a Stage-A adapter assuming zero user echo would mishandle replayed history [T:fork 13.86] | |

**Result: zero part-type changes; zero contract edits.** The five types absorb ACP whole. The only judgment calls are (a) `Custom` kinds for the two housekeeping variants, (b) `plan` collapsed into `Tool`, both already-ruled disciplines in 0049.

### 4.3 The permission round-trip (verbatim, [T:editperm 16.30])

Agent→client request `session/request_permission`:

```json
{"sessionId":"…","toolCall":{"toolCallId":"call_…","title":"/path/hello.txt","kind":"edit","status":"pending",
  "locations":[{"path":"/path/hello.txt"}],
  "rawInput":{"filepath":"/path/hello.txt","diff":"Index: …"},
  "content":[{"type":"diff","path":"/path/hello.txt","oldText":"","newText":"acp-edit\n"}]},
 "options":[{"optionId":"once","kind":"allow_once","name":"Allow once"},
            {"optionId":"always","kind":"allow_always","name":"Always allow"},
            {"optionId":"reject","kind":"reject_once","name":"Reject"}]}
```

Client response result (the shape that took committed evidence to pin down — §5.1):

```json
{"outcome":{"outcome":"selected","optionId":"once"}}
```

or `{"outcome":{"outcome":"cancelled"}}`. This **is** the #1582 consent flow at the protocol level: proposal carries the diff (the user sees exactly what would change), consent is an explicit typed outcome, `allow_always` maps onto our permission-tier persistence (permissiontiers.go) rather than a side-channel `always` array. Sequences observed live: edit-kind with diff content [T:editperm 16.30–16.31], execute-kind [T:perm3 10.43–10.59], and the full failure-and-recovery arc [T:silentignore] — see §5.1.

### 4.4 What we decline

`fs/read_text_file`/`fs/write_text_file` (clientCapabilities set false — the sandbox grants the agent direct PVC access; mediation would be both slower and a new auth path) and the `terminal/*` family (not advertised, not requested in any run; same reason).

## 5. Divergences found (the spec-maturity evidence)

Five findings **against** naive adoption; each is a reason the transport stage is gated (§6.2). All are committed-evidence-backed.

1. **The permission result shape is not the public spec draft, and malformed responses are silently ignored — wedging the turn.** Draft ACP texts show `optionIds: string[]` (plural, array). opencode 1.18.15's bundled zod — and the wire — require `{outcome:{outcome:"selected", optionId}}` **singular**, and `"cancelled"` double-l. The committed capture ([T:silentignore 13.68–52.05]): wrong-shape response → **24+ seconds of total silence** (no parse error, no retry, no timeout; probes at 5/10/15/20s) → the turn is wedged, and a second `session/prompt` sent into the wedge is never evaluated → `session/cancel` **as a notification** unwedges it (first prompt returns `stopReason:"cancelled"`) → a fresh prompt gets a fresh permission request → the correct shape grants and completes (`end_turn`). Three consequences: (a) a malformed consent response fails **closed by inertia** — safety-acceptable but operationally a wedge; (b) JSON-RPC duplicate-id responses are dropped, so shape experiments need one fresh request each; (c) any platform client must treat consent-response shaping as **tested surface**, not spec-assumed — the §8 watchdog is mandatory, not optional.
2. **`session/fork` requires `cwd`** contra its own bundled schema (`cwd: nullish` in the library, [zod extract]): live call without cwd → `-32602 Invalid params: cwd expected string` [T:lifecycle 23.69]; with cwd → new `sessionId` [T:fork 13.86]. The handler is stricter than the library it embeds.
3. **`session/list` spans the shared session store, cross-cwd, and ignores `limit`.** The ACP server in a scratch cwd listed *this workspace's own agent sessions* (including the authoring session itself, [T:lifecycle 23.68]) — and `{limit:10}` returned **24 sessions**, no cursor, despite the schema's `limit`/`cursor` fields [zod extract]. Two divergences in one method: unbounded cross-cwd enumeration. Under transport migration this is a **cross-session visibility surface** the supervisor would need to filter or accept deliberately (today's HTTP surface has the same store but per-cwd filtering in our adapter).
4. **`session/cancel` is notification-only.** The request form returns `-32601 Method not found` (observed during driver iteration; the dispatch table confirms [zod extract]); the notification form works [T:silentignore 37.59]. A client that only sends requests cannot cancel — and a wedged turn (finding 1) is unrecoverable without it.
5. **Emission gaps vs schema:** `plan` never emitted (todowrite → `tool_call kind:"other"` [T:lifecycle 15.76]); `config_option_update`/`current_mode_update`/`session_info_update` never emitted as notifications; `user_message_chunk` emitted **only** on fork/load replay (§3.2), never during prompts. A mapping built for the schema union would carry dead branches — build for the observed seven, keep the union as forward-compat switches.

## 6. The staged path

### 6.1 Stage A — ACP-shaped adapter SSE, now (zero transport change)

US-65.8's SSE bridge and #1582's consent flow are built against our translation vocabulary. Stage A fixes that vocabulary to ACP's names (`tool_call`/`tool_call_update` statuses, `agent_thought_chunk`, the §4.3 consent outcome vocabulary) **inside the existing adapter** — the translate.go output types get ACP-aligned discriminators, while the input remains native SSE. Effect: the frontend contract and the future ACP path converge now; when/if transport migrates, the consumer side is already shaped for it, and #730-class input drift stays quarantined in translate.go's input half. Cost: one adapter-surface rename pass + golden regeneration. **This is the only stage this document requests approval to charter.**

### 6.2 Stage B — transport migration (stdio replacing serve-mode HTTP), assessed NOT scheduled

Today: `managed_process.go:537` spawns `opencode serve --hostname 0.0.0.0 --port <AgentPort>`; agentd consumes HTTP+SSE. ACP alternative: spawn `opencode acp --cwd <workspace>`, speak ndjson JSON-RPC over the same pipe supervisor already owns. Scope found by the spike: the supervisor needs a JSON-RPC framing layer (~the 200-line driver in evidence/, hardened), request/response correlation, and the §5.3 list-filtering decision; it *deletes* the loopback HTTP listener, the SSE reconnection machinery (client_events.go's backoff/resume paths), and agentd's port assignment/liveness-by-HTTP. Boundary: ConfigWriter and the overlay are untouched (§7). Bundle assessment: real but pod-invasive (supervisor process contract changes) — belongs with future pod work, chartered only when a Stage-C trigger fires or a pod lane opens anyway.

### 6.3 Stage C — full adoption triggers (none has fired)

1. **A second agent runtime is funded** (ACP is agent-agnostic; a second runtime doubles the translation tax ACP eliminates).
2. **Editor-direct workspace access is chartered** (Zed et al. speak ACP natively; the platform would expose the pipe, not build a feature).

Until either fires, Stage B stays assessed-only by design.

### 7.1 What the ACP path retires (Stage B+)

| Asset | File(s) | Why |
|---|---|---|
| Per-version SSE goldens | `pkg/agent/opencode/testdata/golden/sse_events_1_18_{10,15}_live_abi.want.jsonl` | the native event stream is no longer consumed; replaced by a small ACP-round-trip golden per §5 divergence set |
| Native event dialect | `pkg/agent/opencode/dialect.go` (243 lines: `per_`/`que_` prefixes, `/permission/{id}/reply` paths, `permission.asked/replied` prop shapes) | superseded by `session/request_permission` (typed, §4.3) |
| SSE→contract translation (input half) | `pkg/agent/opencode/translate.go` ~1,000 lines; `client_events.go` event switch (`message.part.delta`, `session.next.*`, `session.status`, …) | the eleven-variant `sessionUpdate` union replaces the event zoo; output half survives as the part mapper |
| History fetch+parse | `agent_client.go` history path (the #730 outage site) | `session/load` + replayed updates are the ACP-native history; #730's parser class deletes |
| Loopback HTTP liveness | port assignment, SSE reconnect/backoff | stdio pipe death is liveness |

### 7.2 What remains either way

- **ConfigWriter + overlay + permission tiers** (`configwriter*.go`, `permissiontiers*.go`): ACP has no agent-configuration surface (its `configOptions` are per-session model/mode selectors — verified live — not the overlay contract). The #1582 consent UX (tier persistence of `allow_always`) also stays platform-side.
- **The contract itself** (design 0049 parts, OpenAPI, SDKs): unaffected — §4.2 lands ACP *inside* it.
- **Output-side translation** (part mapping, FileChange hunk assembly): renamed, not deleted.
- **Version pinning discipline**: ACP's stability commitment is upstream's practice, not a contract with tests. The pin matrix (opencode_pins.go) and a capture-per-bump cadence remain, but the captured surface shrinks from "everything SSE+HTTP" to "the ACP divergences of §5".

### 7.3 Net

The #730 tax has two halves: **shape drift** (what broke) and **capture cost** (what detects). ACP moves both: shape drift onto a surface opencode maintains for external clients (their incentive to keep it stable), capture cost down to a ~5-assertion divergence golden (§5's list is the v0 of that fixture).

## 8. Spec-maturity risk register

|---|---|---|

| consent-response shape drift (§5.1) | silent wedge (no error signal) | per-bump ACP round-trip golden incl. a consent denial + grant **and a wrong-shape probe**; inactivity watchdog on the pipe with notification-cancel recovery drill |
