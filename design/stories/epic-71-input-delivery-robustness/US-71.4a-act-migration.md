# US-71.4a — Input/permissions edge migration: replies through Act, one contract shape

**Issue:** [#1302](https://github.com/lenaxia/LLMSafeSpaces/issues/1302) · **Epic:** [#1314](https://github.com/lenaxia/LLMSafeSpaces/issues/1314) (stream 4a) · **Prerequisite:** #828 batch-3 (#1357, MERGED 2026-09-13) · **Lineage:** #1313 (3a — the inbox this builds on), #1324 (1a — `AnswerInputAction.reply`)

**Status:** in implementation. Post-batch-3 delta analysis below is the authoritative remaining-work map.

## What batch-3 already landed (do not re-do)

The five input routes are adapter-only with typed 503s/502s, guards, quota+metering, and two new adapter methods (`AnswerQuestion`, `ReplyPermission`); the raw-proxy tails (fetchFromPod/parse*/dialect guards) are deleted; the inbox walk-away interactions are preserved.

## Remaining delta (this stream)

### 1. Write path through `Act` (S1: the API makes zero mutating harness calls)

`QuestionReply`/`QuestionReject`/`PermissionReply` — and
`DismissInboxRecord`'s live reject (added by the r1 review: the route
was missing from this map, and S1 has no carve-outs) — go through
**agentd `Act` with `AnswerInputAction`** (the
`SessionAction`/`proxy_actions.go` forwarding shape), replacing
adapter-direct mutating opencode HTTP:

| Route | Action payload | Agentd routing |
|---|---|---|
| `QuestionReply` | `option_ids = answers[0]` (labels and/or free text — the harness wire takes them in one array; agentd's Actor already rebuilds `{"answers":[[option_ids…+custom]]}` byte-compatibly) | existing: `/question/{id}/reply`, 404→permission |
| `PermissionReply` | `reply = once\|always\|reject` (+ `message`, see decision D2) | existing: `/permission/{id}/reply` |
| `QuestionReject` | `reply = "reject"` | **D1 (r6/r8 corrected):** `que_`-prefixed ids reject on `/question/{id}/reject` ONLY — the 404 is the absence signal for the fold; `per_`-prefixed ids go straight to `/permission/{id}/reply` (the harness prefix-validates; cross-kind posts are 400 Params, never 404) |
| `DismissInboxRecord` (live ask) | `reply = "reject"` | same D1 routing (r1: the route joined the S1 map) |

**D1 — question-reject rides the existing `reply` vocabulary.** The
proto comment for `reply = 4` already reads `"once"|"always"|"reject"`
(#1310 slice A / #1302). A reject on a question id is the dismiss exit.
**r6/r7 correction:** the harness PREFIX-VALIDATES request IDs (captured
live: a cross-kind post is a 400 Params error, never a 404) — routing is
prefix-aware at every site (the actor's reject AND legacy answer forms,
`Adapter.RejectInput`, `Adapter.Resolve`); a prefixed id never posts
cross-kind, and the 404 from the ask's OWN kind is the absence signal
the resolve-by-absence fold consumes. Unprefixed ids keep the probe
order. No contract change.

**D2 — deny-feedback `message` needs one additive field.** Batch-3's own
bar was "preserves the message field the passthrough carried"; the action
contract cannot carry it today. Add `optional string message = 5` to
`AnswerInputAction` (buf regen; breaking-safe; disjointness rules
unchanged — message only valid WITH `reply`). Agentd forwards it on the
permission reply body. This stays within #1302's additive-delta spirit;
recorded as a deliberate extension, not silent scope creep.

**S6 (absence = resolution):** agentd's resolve-by-absence (1a, #1324)
makes an `Act` answer against a dead ask return SUCCESS with the
projection resolved. Reachability, stated precisely (r1 f3): the reply
routes' `tryLateAnswer` intercepts dead asks WITH inbox records into the
outbox walk-away flow BEFORE Act — the resolve-by-absence path serves
dead asks WITHOUT records on `QuestionReject` (where the record
identifies the session but the harness ask is gone) and the generic
actions route. **Dead-ask clear for other tabs:** every disposition
terminalizing a record publishes `agent.*.resolved` (r1 f2 — a dead ask
has no harness INPUT_RESOLVED coming; duplicates for live asks are
idempotent by request ID client-side). A live set that cannot be READ
(`ListPending` error, no identifying record) answers 503
non-authoritatively — never an authoritative 404 (r1 robustness). The
e2e asserts the end-to-end clear (increment 2's S6/L2 legs).

**Inbox disposition hook (3a's deferred item):** on `Act` success in the
three routes AND in the generic `SessionAction` route
(`answer_question`): `reply=="reject"` → record terminalized
**dismissed**; otherwise **answered** (same `publishInboxResolved`
clear-for-other-tabs event).

### 2. One contract shape on REST + SSE (#1302 items 1/4/6)

`toQuestionRequest`/`toPermissionRequest` (the `agent.QuestionRequest`/
`PermissionRequest` legacy envelopes) retire. REST lists return
`session.InputRequest` (root-session resolved — the contract type HAS
`RootSessionID`). The SSE snapshot emits `InputRequest` in `evt.Data`.

**D3 — `whileAway` rides the SSE envelope, not the ABI.** InputRequest
is generated from the agent-facing ABI proto; a browser-only
re-presentation marker does not belong on the agent contract.
`apitypes.WorkspaceSSEEvent` (platform-owned) gains
`WhileAway *bool json:"whileAway,omitempty"` — set on inbox-only
re-presentations; the frontend reads the envelope flag + `evt.data` as
`InputRequest`.

### 3. Prefix validation behind the seam (#1302 item 3)

`questionIDPattern`/`permissionIDPattern` (opencode `que_`/`per_`
prefixes baked into handler validation — design 0049 discipline rule 2)
are replaced by the generic request-ID contract: charset
`[a-zA-Z0-9._-]`, length ≤128, no `..` (mirrors `validateSessionID`).
The `que_`/`per_` literals move to `pkg/agent/opencode/dialect.go`
(kind-by-prefix helpers for the reject-routing fallback, where the
harness's own endpoints already discriminate).

### 4. OpenAPI + frontend

`InputRequest` component schema (mirror `pkg/session` contract_gen json
tags); retype the four read routes; drop `x-opencode-proxy` markers.
Frontend: `QuestionRequest`/`PermissionRequest` types replaced by the
`InputRequest` shape across `api/types.ts`, the provider, prompt
components, and the Playwright stubs. **Canary note (grep finding):**
`sdks/canary` asserts status codes only (`200 || 204` on
permission-reply) — the 3a late-answer `202` can trip it in a dead-ask
window; widen the canary assert to `2xx` in this stream (it consumes no
shapes).

## Test plan (README §0; extends #1302's)

**Agentd:** reject-routing rows (question id → question-reject endpoint;
permission id → fallback); message forwarding; answer wire parity.
**API handlers:** the five routes through `Act` (happy, transport 502,
invalid-ID 400 under the GENERIC rule — `que_`-prefixed and bare IDs
both accepted, 503 non-authoritative lists unchanged); disposition hook
rows (answered / dismissed-on-reject / SessionAction path).
**Emitter parity:** SSE-emitted `InputRequest` deep-equals REST
`ListPending` output for the same pending set; envelope `whileAway` only
on inbox-only records.
**OpenAPI:** contract test picks up the retyped routes (no
`x-opencode-proxy` on them).
**Frontend:** vitest retypes + Playwright stub updates.
**E2E (kind):** the S6 stale-click leg (reply against a dead ask clears
everywhere, never a silent no-op) + L2 ≤2s clear.
