# US-63.3: Enqueue Path — POST Prompt with `delivery: "queue"`; Remove 409 Guard

**Epic:** 63 - Inboard Session Queue
**Priority:** Critical
**Depends on:** US-63.2 (V2 client)

## User Story

As a user typing while a session is busy, I want my message to be durably admitted to opencode's inboard queue — so that it is processed after the in-flight turn without a proxy-side Redis queue, drain loop, or 409 retry.

## Background

Today, `EnqueueMessage` (`proxy_handlers.go:907`) writes to Redis and triggers `drainQueuedMessage`; `SendPromptAsync` (`proxy_handlers.go:73`) guards with a 409 when `isSessionActive` and otherwise forwards to V1 `/prompt_async`. Both paths carry the message-id hack and the false-idle requeue machinery.

opencode's V2 `POST /api/session/:sid/prompt` with `delivery: "queue"` admits atomically: it never 409s on busy, it durably persists the input, and it self-drains on the next idle (Epic 63 F8, F9). The proxy becomes a thin forwarder.

## Acceptance Criteria

- [ ] `EnqueueMessage` (when `v2SessionQueueEnabled`): calls `client.PromptV2(..., { delivery: "queue" })` instead of `queueSvc.Enqueue`. The Redis write path is unreachable under the flag.
- [ ] `SendPromptAsync` (when `v2SessionQueueEnabled`): calls `client.PromptV2(..., { delivery: "queue" })` directly. The 409 guard (`isSessionActive` check at `proxy_handlers.go:80-87`) is **bypassed** under the flag — opencode admits atomically and never 409s on busy.
- [ ] `redirectPromptToQueue` (`proxy_handlers.go:114`) is **unreachable** under the flag (the queue-len check that triggers it is skipped).
- [ ] The `queue.update` → `enqueued` SSE event is still published on successful admission (US-63.5 may later derive it from the V2 `PromptAdmitted` event; for now the proxy emits it on V2 success to preserve frontend behavior).
- [ ] The legacy Redis path remains the default (flag off); both paths coexist for the rollout.
- [ ] E2E tests (feature-flagged) cover: enqueue while idle → runs; enqueue while busy → runs after current turn; enqueue then abort-while-queued → queued message survives (cross-references US-63.4).
- [ ] Unit tests cover the flag-on path; existing `proxy_queue_test.go` tests for the flag-off path still pass unchanged.

## Assumptions

| # | Assumption | Validation |
|---|---|---|
| A1 | V2 `prompt` with `delivery: "queue"` never returns 409 when the session is busy (opencode admits regardless of runner state) | US-63.1 spike confirms the busy-enqueue case. |
| A2 | The V2 admit is durable enough that the proxy does not need its own retry/backoff | Epic 63 F8 (durability via event-sourced `SessionInputTable`); the spike confirms no transient-error surface. |

## Technical Details

The flag is checked at the top of `EnqueueMessage` and `SendPromptAsync`. The response-handling (extracting any opencode-generated message ID for the `enqueued` SSE event) follows the spike's recorded body shape.

The `maxQueueRetries` budget, `errSessionBusy`, and the 409-requeue branch (`proxy_events.go:460-474`) become dead code under the flag and are deleted in US-63.7.
